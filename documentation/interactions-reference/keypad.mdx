## What is Keypad?

Keypad is a mobile-specific interaction designed for entering numbers using on-screen numeric keypads. When mobile apps display a numeric keypad (like PIN entry, phone number input, or verification codes), this interaction simulates tapping the number buttons just like a real user would.

Think of it as the mobile equivalent of typing numbers, but instead of a keyboard, you're tapping individual number buttons displayed on the screen.

## When to Use Keypad

Keypad should be used in very specific scenarios—when ALL of these conditions are met:

### Required Conditions (ALL must be true)

1. **Platform is Mobile**: There's an on-screen numeric keypad displayed
2. **Keypad is visible**: The numeric buttons are rendered on screen as tappable elements
3. **You need to input numbers**: You're entering digits (0-9)

### Common Scenarios

#### Scenario 1: PIN Entry

Mobile banking or security apps with PIN screens:

```
Step 1: Navigate to the PIN entry screen
Step 2: Keypad 1234
Step 3: Verify I see the secure area
```

#### Scenario 2: Phone Number Input

Dialer interfaces or phone number entry:

```

Step 2: Keypad 5551234567
Step 3: Click the call button
Step 4: Verify the call initiated
```

#### Scenario 3: Verification Codes

Two-factor authentication with numeric codes:

```

Step 2: Keypad 123456
Step 3: Verify I see the success message
```

#### Scenario 4: Credit Card Entry

Mobile checkout with keypad for card numbers:

```

Step 2: Keypad 4111111111111111
Step 3: Click the CVV field
Step 4: Keypad 123
Step 5: Click the submit button
```

#### Scenario 5: Passcode Lock Screens

App lock screens or secure folder access:

```

Step 2: Wait until I see the passcode screen
Step 3: Keypad 987654
Step 4: Verify I see the notes list
```

### When NOT to Use Keypad

Don't use Keypad when:

- **Testing on Web**: Use Input Text instead (no on-screen keypad)
- **No visible keypad**: The field uses a standard keyboard, not a keypad
- **Entering non-numbers**: Letters, symbols, or mixed alphanumeric (use Input Text)
- **The user didn't explicitly mention keypad**: Default to other input methods
- **Standard input field**: If it's a regular text input that happens to accept numbers

### Critical Rule: Only Use When Keypad is On-Screen

The Keypad interaction is **only** for visible on-screen numeric keypads. If you see a standard mobile keyboard (even if it shows numbers), don't use Keypad—use Input Text or Input on Focus instead.

## How It Works

The Keypad interaction:

1. **Identifies keypad buttons**: Locates the on-screen numeric buttons (0-9)
2. **Taps in sequence**: Simulates tapping each digit in order
3. **No field location**: Doesn't search for an input field (assumes keypad is for the active input)
4. **Direct button interaction**: Interacts with the keypad buttons themselves, not a text field

### What Happens Behind the Scenes

```
User prompt: Keypad 1234

Autonoma:
1. Finds the "1" button on the keypad → Taps it
2. Finds the "2" button on the keypad → Taps it
3. Finds the "3" button on the keypad → Taps it
4. Finds the "4" button on the keypad → Taps it
```

Each tap sends the digit to the focused input element.

## Platform Support

- **Web**: Not supported (no on-screen keypads)
- **Mobile**: Fully supported (iOS and Android)

This is a **mobile-only interaction** because on-screen numeric keypads are a mobile UI pattern.

## Understanding Metadata

The metadata for Keypad is the sequence of digits to tap:

**Prompt**: `keypad 1234`
**Metadata**: `1234`

**Prompt**: `type 3267 on the keypad`
**Metadata**: `3267`

**Prompt**: `input 123456 on keypad`
**Metadata**: `123456`

The metadata contains only the digits—no spaces, dashes, or formatting.

### Formatting Numbers

If you need to input formatted numbers (like phone numbers), provide the raw digits:

**For phone number (555) 123-4567**:
- **Prompt**: `keypad 5551234567`
- **Metadata**: `5551234567`

The keypad only handles digits, not formatting characters.

## Best Practices

### 1. Verify Keypad is Visible

Before using Keypad, ensure the keypad is actually displayed:

**Good**:
```
Step 1: Click the PIN field
Step 2: Wait until I see the numeric keypad
Step 3: Keypad 1234
```

**Bad**:
```
Step 1: Click the PIN field
Step 2: Keypad 1234  // What if keypad hasn't appeared yet?
```

### 2. Use Only for On-Screen Keypads

Don't use Keypad for regular input fields:

**Correct use** (visible keypad):
```
Step 1: Navigate to PIN screen
Step 2: Keypad 1234
```

**Incorrect use** (regular input):
```
Step 1: Click the age field  // Shows regular keyboard, not keypad
Step 2: Keypad 25  // Should use Input Text
```

### 3. Provide Raw Digits Only

Don't include formatting in the metadata:

**Good**: `keypad 5551234567`
**Bad**: `keypad (555) 123-4567`
**Bad**: `keypad 555-123-4567`

The keypad only has digit buttons (0-9).

### 4. Verify Input Was Accepted

After entering numbers, verify they were accepted:

```
Step 1: Keypad 1234
Step 2: Verify I see ••••  (masked PIN display)
Step 3: Click submit
```

### 5. Wait for Dynamic Keypads

Some keypads appear dynamically or with animation:

```
Step 1: Click the security field
Step 2: Wait until the keypad animation completes
Step 3: Keypad 1234
```

### 6. Test Different Number Lengths

Test various input lengths your app supports:

```
// Test 4-digit PIN
Test 1: Keypad 1234

// Test 6-digit PIN
Test 2: Keypad 123456

// Test phone number
Test 3: Keypad 5551234567
```

### 7. Handle Keypad Special Buttons

Some keypads have backspace or clear buttons:

```
Step 1: Keypad 1234
Step 2: Verify I see 4 digits entered
Step 3: Click the backspace button
Step 4: Verify I see 3 digits entered
Step 5: Keypad 5
Step 6: Verify I see 1235
```

## Common Pitfalls

### Pitfall 1: Using Keypad on Web

**Problem**: Keypad doesn't work on web platforms.

**Example**:
```
// Web test - WRONG
Step 1: Navigate to PIN field
Step 2: Keypad 1234  // Fails - no keypad on web
```

**Solution**: Use Input Text on web:
```
Step 1: input 1234 on the PIN field
```

### Pitfall 2: Using Keypad When No Keypad is Visible

**Problem**: You use Keypad but the UI shows a regular keyboard.

**Example**: Clicking an age field might show a regular number keyboard, not a keypad.

**Solution**: Use Input Text or Input on Focus:
```
Step 1: input 25 on the age field
```

### Pitfall 3: Including Formatting Characters

**Problem**: Trying to input formatted numbers with dashes or parentheses.

**Example**:
```
Keypad (555) 123-4567  // Won't work - keypad only has digits
```

**Solution**: Use raw digits:
```
Keypad 5551234567
```

### Pitfall 4: Not Waiting for Keypad to Appear

**Problem**: Trying to use Keypad before it's rendered.

**Example**:
```
Step 1: Click the PIN field
Step 2: Keypad 1234  // Might fail if keypad hasn't appeared
```

**Solution**: Add a wait step:
```
Step 1: Click the PIN field
Step 2: Wait until I see the keypad
Step 3: Keypad 1234
```

### Pitfall 5: Using When User Didn't Specify

**Problem**: Automatically using Keypad when a simpler method would work.

**Rule**: Only use Keypad when:
- User explicitly says "keypad", OR
- On-screen keypad is visible AND user wants to input numbers

**Example**:
```
User: "Input 1234 on the field"
Wrong: Keypad 1234  // User didn't mention keypad
Right: input 1234 on the field
```

### Pitfall 6: Confusing Keypad with Regular Number Input

**Problem**: Using Keypad for regular number fields.

**Mobile number input field with regular keyboard**:
```
Wrong: Keypad 25  // This is a regular input, not a keypad
Right: input 25 on the age field
```

**Mobile PIN screen with keypad buttons**:
```
Right: Keypad 1234  // This is an on-screen keypad
```

### Pitfall 7: Not Handling Keypad Variations

**Problem**: Different apps have different keypad layouts.

**Examples**:
- Randomized keypads (security feature)
- Keypads with additional buttons (., *, #)
- Keypads with biometric buttons

**Solution**: Test your specific keypad layout and adjust as needed.

## Mobile Keypad Types

Different types of keypads you might encounter:

### 1. Standard PIN Keypad

```
[1] [2] [3]
[4] [5] [6]
[7] [8] [9]
    [0]
```

**Use**: Bank PINs, app locks, security codes

### 2. Phone Dialer Keypad

```
[1]   [2]   [3]
[4]   [5]   [6]
[7]   [8]   [9]
[*]   [0]   [#]
```

**Use**: Phone calls, USSD codes

**Note**: Keypad interaction typically handles digits only, not * or #.

### 3. Randomized Security Keypad

```
[7] [2] [9]
[4] [1] [3]
[8] [6] [0]
    [5]
```

**Use**: High-security apps (bank transfers, crypto wallets)

**Challenge**: Button positions change each time for security.

### 4. Calculator-Style Keypad

```
[7] [8] [9]
[4] [5] [6]
[1] [2] [3]
[0] [.] [=]
```

**Use**: Calculator apps, price entry

### 5. Credit Card Keypad

```
[1] [2] [3]
[4] [5] [6]
[7] [8] [9]
[⌫] [0] [✓]
```

**Use**: Payment entry, CVV input

## Comparing Input Methods on Mobile

| Method | Use Case | Keypad Type |
|--------|----------|-------------|
| **Keypad** | On-screen numeric buttons | Visible numeric keypad |
| **Input Text** | Regular input fields | Standard mobile keyboard |
| **Input on Focus** | Already-focused fields | Any keyboard type |

**Decision rule**: If you see individual number buttons on screen that you tap, use Keypad. Otherwise, use Input Text.

## Accessibility Considerations

Keypad interactions are generally accessible on mobile:

- **Large touch targets**: Keypad buttons are typically large and easy to tap
- **Haptic feedback**: Physical vibration on tap
- **Audio feedback**: Sound on button press
- **Visual feedback**: Button press animations

**Testing tip**: Ensure keypad buttons are large enough for users with motor disabilities (minimum 44x44 points on iOS, 48x48 dp on Android).

## Debugging Keypad Issues

### Issue: Keypad Not Found

**Error**: "Could not find keypad"

**Debugging steps**:
1. Verify you're on mobile platform (not web)
2. Check if keypad is actually visible on screen
3. Ensure field is focused before keypad appears
4. Add wait: `Wait until I see the keypad`

### Issue: Wrong Digits Entered

**Debugging steps**:
1. Verify metadata contains only digits
2. Check for typos in the number
3. Ensure keypad buttons are correctly labeled
4. Test with single digit first: `Keypad 1`

### Issue: Keypad Appears but Interaction Fails

**Debugging steps**:
1. Check if keypad is custom-styled (might not be recognized)
2. Try clicking individual number buttons instead
3. Verify the keypad isn't an image or non-interactive element
4. Check if JavaScript is blocking interaction

### Issue: Should Use Keypad but Using Input Text

**When to switch**:
- If you see on-screen numeric buttons
- User explicitly mentions "keypad"
- Traditional PIN/passcode entry screen

**How to fix**: Replace Input Text with Keypad:
```
Before: input 1234 on the PIN field
After: Keypad 1234
```

## Key Takeaways

1. **Keypad is mobile-only** for on-screen numeric button entry
2. **Only use when ALL conditions met**: Mobile platform + visible keypad + numeric input
3. **Metadata is digits only**—no formatting or special characters
4. **Prioritize over other methods** when keypad is on screen and user wants to input numbers
5. **Wait for keypad to appear** before interaction
6. **Don't use on web**—use Input Text instead
7. **Common uses**: PIN entry, phone dialers, verification codes, secure inputs
8. **Verify input was accepted** after entering numbers
9. **User must mention keypad** OR keypad must be visible to use this interaction
10. **Different from Input Text**—taps buttons vs. typing in field

## Related Interactions

- **Input Text**: Standard text input for web and regular mobile fields
- **Input on Focus**: Type into focused fields (mobile and web)
- **Backspace**: Delete entered digits from keypad
- **Click**: Tap individual keypad buttons (alternative to Keypad interaction)
- **Wait**: Ensure keypad is visible before interaction

## Decision Framework

Use this decision tree to choose the right interaction:

```
Need to input numbers on mobile?
│
├─ Is there a visible on-screen numeric keypad?
│  │
│  ├─ Yes → Are there individual digit buttons (0-9)?
│  │        │
│  │        ├─ Yes → Use Keypad
│  │        └─ No → Use Input Text
│  │
│  └─ No → Is it a regular input field?
│           │
│           ├─ Yes → Use Input Text
│           └─ No → Verify the UI type
│
└─ On web platform?
   └─ Use Input Text (no keypads on web)
```
