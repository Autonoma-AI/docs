## What It Does

OCR Scroll is a specialized scrolling interaction that uses Optical Character Recognition (OCR) to locate text elements within specific scrollable containers, then scrolls in the direction needed. Unlike regular scroll interactions that affect the main page or screen, OCR Scroll can target nested scrollable areas like modal dialogs, sidebar panels, embedded lists, or any UI component with its own scroll behavior.

Think of it like scrolling within a window inside a window. Your main page might scroll, but there's also a pop-up dialog with its own scrollable content. OCR Scroll lets you control that inner scroll area by identifying text landmarks through visual recognition.

## When to Use It

Use OCR Scroll when:

- **Nested scrollable areas** - Modal dialogs, popups, or panels with independent scrolling
- **Scrollable containers** - Embedded lists, sidebars, or content boxes within the page
- **Complex UI layouts** - Multi-panel interfaces where multiple areas can scroll
- **Shadow DOM elements** - Components that are hard to target with regular selectors
- **iFrames or embedded content** - Content within frames that scroll independently
- **Custom scrollbars** - Elements with non-standard scroll implementations
- **Text-based navigation** - When you need to find and scroll to specific text

**Don't use it when:**
- Scrolling the main page or screen - Use regular **Scroll** instead
- You know the scroll count and area is straightforward - Use **Scroll** or **Scroll With Condition**
- Working with standard horizontal carousels - Use **Move Carousel** instead
- Element doesn't contain text for OCR to recognize

## Platform Support

- **Web**: Yes
- **Mobile**: Yes (iOS and Android)

OCR Scroll is particularly valuable on mobile where nested scrollable containers are common in app interfaces.

## How It Works

OCR Scroll uses computer vision to:

1. **Scan the screen** for text elements
2. **Identify** the scrollable container containing the target text
3. **Determine** which direction to scroll
4. **Execute** the scroll within that specific container

**Basic usage**:
```
OCR scroll: up
```

**Multiple scrolls**:
```
OCR scroll: down 2 times
```

**Directional scrolling**:
```
OCR scroll: left 3 times
```

The metadata is always a number representing how many times to scroll. If you don't specify, it defaults to 1.

## Four-Directional OCR Scrolling

OCR Scroll supports all four directions:

### Vertical Scrolling

**Down** - Most common for content:
```
OCR scroll: down
```
- Reveals content below in the container
- Reading through lists, articles, reviews

**Up** - Going back to previous content:
```
OCR scroll: up
```
- Returns to earlier content
- Navigating to top of container
- Finding older items in lists

### Horizontal Scrolling

**Right** - Moving to next content:
```
OCR scroll: right
```
- Horizontal lists or galleries within containers
- Tab panels with horizontal overflow
- Wide tables that scroll horizontally

**Left** - Moving to previous content:
```
OCR scroll: left
```
- Returning to earlier horizontal content
- Back through image galleries
- Navigating wide data tables

**Example using multiple directions**:
```
Test: "Navigate complex scrollable grid"

1. Click: Data grid container
2. OCR scroll: down 5 times ← Vertical navigation
3. Wait: 1 second
4. OCR scroll: right 3 times ← Horizontal navigation
5. Assert: Target cell visible
```

## Understanding Metadata: The Scroll Count

OCR Scroll requires metadata: a number indicating how many times to scroll.

**Important**: The metadata must be a NUMBER, not a string.

```
Correct: 3
Incorrect: "3"
Incorrect: "three"
```

**How to specify in your test**:

```
OCR scroll: down      ← Defaults to 1 scroll
OCR scroll: down 2    ← Scrolls 2 times
OCR scroll: up 5      ← Scrolls up 5 times
OCR scroll: left 3    ← Scrolls left 3 times
```

## How OCR Identifies the Target Container

OCR Scroll uses visual text recognition to determine where to scroll:

1. **Scans visible text** on the entire screen
2. **Identifies scrollable containers** that contain text
3. **Targets the appropriate container** based on context
4. **Executes scroll** within that specific area

**The AI determines the target intelligently** based on:
- Visible text elements
- Container boundaries
- UI context
- Your test's prior actions

## OCR Scroll vs Regular Scroll

Understanding the difference is crucial:

### Regular Scroll
- Scrolls the **main page/screen**
- Affects the primary viewport
- Simpler and faster
- Works for standard layouts

### OCR Scroll
- Scrolls **specific containers**
- Targets nested scrollable areas
- Uses OCR to identify context
- Works for complex layouts

**Example comparison**:

```
// Regular scroll - affects main page
1. Scroll: down 5 times ← Main page scrolls

// OCR scroll - affects container
1. OCR scroll: down 5 times ← Modal/panel scrolls
```

**When you have a modal open**:
- **Regular Scroll**: Might try to scroll the page behind the modal
- **OCR Scroll**: Scrolls within the modal itself

## Best Practices

### 1. Activate the Container First

Click or focus the container before scrolling:

```
Good:
1. Click: Inside review panel ← Activate focus
2. OCR scroll: down 3 times

Risky:
1. OCR scroll: down 3 times ← Might target wrong area
```

### 2. Add Waits Between Scrolls

Give content time to render:

```
Good:
1. OCR scroll: down 5 times
2. Wait: 1 second ← Content settles
3. Assert: Element appears

Risky:
1. OCR scroll: down 5 times
2. Assert: Element appears ← Might not be rendered yet
```

### 3. Be Patient With Multiple Scrolls

Break up large scroll counts:

```
Better:
1. OCR scroll: down 5 times
2. Wait: 1 second
3. OCR scroll: down 5 times
4. Wait: 1 second

Aggressive:
1. OCR scroll: down 10 times ← Might be too fast
```

### 4. Verify the Container is Scrollable

Ensure the container actually has scrollable content:

```
1. Assert: Container has more content below
2. OCR scroll: down 3 times
3. Assert: New content visible
```

### 5. Combine With Regular Scroll for Multi-Level Navigation

```
// Get to the section with the container
1. Scroll: down 5 times ← Main page

// Interact with container
2. Click: Open modal
3. Wait until: Modal visible

// Scroll within container
4. OCR scroll: down 3 times ← Modal content
```

## Common Pitfalls

### Pitfall 1: Using OCR Scroll for Main Page

**Problem**:
```
1. OCR scroll: down 10 times ← Should use regular Scroll
```

**Why it's wrong**: OCR Scroll is for containers, not main pages.

**Solution**:
```
1. Scroll: down 10 times ← Use regular Scroll for main page
```

### Pitfall 2: Not Waiting for Container to Load

**Problem**:
```
1. Click: Open modal
2. OCR scroll: down 3 times ← Modal might not be ready
```

**Why it fails**: Container isn't fully loaded.

**Solution**:
```
1. Click: Open modal
2. Wait until: Modal content loads ← Critical wait
3. OCR scroll: down 3 times
```

### Pitfall 3: Scrolling Too Fast

**Problem**:
```
1. OCR scroll: down 20 times
2. Assert: Bottom element visible ← Might not have rendered
```

**Why it fails**: Content can't keep up.

**Solution**:
```
1. OCR scroll: down 10 times
2. Wait: 2 seconds ← Let content load
3. OCR scroll: down 10 times
4. Wait: 2 seconds
5. Assert: Bottom element visible
```

### Pitfall 4: Using in Simple Scenarios

**Problem**:
```
// Simple page with no nested containers
1. OCR scroll: down 5 times ← Overcomplicated
```

**Why it's wrong**: Regular scroll would be simpler.

**Solution**:
```
1. Scroll: down 5 times ← Simpler for standard pages
```

### Pitfall 5: Container Has No Text for OCR

**Problem**:
```
// Container with only images, no text
1. OCR scroll: down 3 times ← OCR can't find text landmarks
```

**Why it fails**: OCR needs text to identify context.

**Solution**:
```
// Use different approach for text-free containers
1. Add prompt: "Scroll within the image gallery"
Or
1. Click specific visible image to focus, then scroll
```

### Pitfall 6: String Instead of Number for Metadata

**Problem**:
```
OCR scroll: down "3" times ← Will cause an error
```

**Why it fails**: Metadata must be a number.

**Solution**:
```
OCR scroll: down 3 times ← Correct
```

## Performance Considerations

OCR Scroll is more computationally intensive because it:

1. **Analyzes the visual screen** for text
2. **Identifies containers** through image recognition
3. **Determines scroll context** from visual clues

**Best practices for performance**:

```
// Give OCR time to process
1. Click: Container
2. Wait: 1 second ← Let container stabilize
3. OCR scroll: down 3 times
4. Wait: 1 second ← Let OCR re-analyze

// Avoid excessive rapid scrolling
Good: OCR scroll: down 5 times, wait, scroll 5 more
Avoid: OCR scroll: down 50 times in one go
```

### Check: Is there visible text in the container?

### Check: Did you focus/activate the container?
