## What is cURL?

The cURL interaction allows you to execute pre-configured HTTP requests using command-line cURL syntax that you've stored in Autonoma's database. If you're familiar with making API calls from the terminal using `curl`, this interaction brings that same power and flexibility into your Autonoma tests.

Like the Fetch interaction, cURL lets you save complex HTTP requests with all their configuration details and then execute them with a simple natural language command. The key difference is that cURL gives you command-line level control with access to all cURL's features and flags.

This is particularly valuable when:
- You need very specific HTTP request configurations
- You're working with legacy APIs that have unusual requirements
- You're debugging API integrations and need fine-grained control
- You have existing cURL commands from API documentation you want to replicate
- You need features specific to cURL (custom protocols, complex authentication, etc.)

## When to Use cURL vs Other Approaches

Understanding when cURL is the right choice helps you build more maintainable tests.

### Use cURL when:

**Replicating existing cURL commands**
```
Your API documentation provides cURL examples
You want to use them directly in your tests without translation
```

**Complex authentication schemes**
```
APIs requiring client certificates
Custom authentication headers not standard in REST APIs
Multi-step authentication flows
```

**Fine-grained HTTP control**
```
Need to set specific HTTP version
Require custom timeouts or retry logic
Need to control cookies, redirects, or caching
```

**Binary data or file uploads**
```
Testing file upload functionality
Multipart form data submissions
Binary protocol testing
```

**Debugging API issues**
```
Need to see exact headers sent and received
Want to test specific edge cases
Investigating integration problems
```

**Non-standard HTTP scenarios**
```
Custom protocols beyond HTTP/HTTPS
Unusual header requirements
Legacy system integration
```

### Use Fetch instead when:

**Standard REST API testing**
```
Modern JSON-based APIs
Standard authentication (Bearer tokens, API keys)
Typical CRUD operations
```

**Simplicity is preferred**
```
You don't need command-line specific features
Standard Fetch API patterns work fine
Team is more familiar with Fetch than cURL
```

**Promise-based async patterns**
```
Your application uses Fetch API natively
You want modern JavaScript-style syntax
```

## cURL vs Fetch: Technical Comparison

### cURL (Command-line style)

**Strengths:**
- Complete control over HTTP request details
- Access to all cURL command-line flags
- Native file upload support
- Certificate and security options
- Follows redirects with full control
- Cookie handling
- Verbose debug output

**Best for:**
- Complex scenarios requiring fine control
- Replicating documentation examples
- Legacy API integration
- File uploads and downloads
- Certificate-based authentication

**Example cURL commands:**
```bash
curl -X POST https://api.example.com/upload \
  -H "Authorization: Bearer token" \
  -F "file=@document.pdf" \
  -F "title=My Document"

curl -X GET https://api.example.com/users \
  --cert client.pem \
  --key client.key \
  -v

curl -X PUT https://api.example.com/resource \
  -H "Content-Type: application/json" \
  -d '{"name":"value"}' \
  --max-time 30 \
  --retry 3
```

### Fetch (JavaScript style)

**Strengths:**
- Clean, modern syntax
- JSON-first approach
- Standard web API patterns
- Simpler for typical REST operations
- Better for teams unfamiliar with cURL

**Best for:**
- Standard REST APIs
- JSON request/response patterns
- Modern web application testing
- Simple CRUD operations

**When to switch from Fetch to cURL:**
- Fetch is failing for complex scenarios
- API documentation only provides cURL examples
- You need cURL-specific features (certificates, advanced options)
- File uploads require multipart/form-data
- You need verbose debugging output

## How It Works

When you use the cURL interaction:

1. **Script Lookup**: Autonoma retrieves your stored cURL command by name
2. **Configuration Loading**: The complete cURL command with all flags and options is loaded
3. **Request Execution**: Autonoma executes the cURL command exactly as configured
4. **Response Capture**: Headers, body, and status codes are captured
5. **Validation**: You can extract data from the response and verify results

### Typical cURL Script Structure

A cURL script you've stored might look like this:

```bash
curl -X POST https://api.example.com/orders \
  -H "Authorization: Bearer {{variable:AUTH_TOKEN}}" \
  -H "Content-Type: application/json" \
  -d '{
    "items": [
      {"product_id": "{{key:PRODUCT_ID}}", "quantity": 1}
    ],
    "customer_id": "{{key:CUSTOMER_ID}}"
  }'
```

When you execute this with "execute the cURL command called CREATE_ORDER", Autonoma runs this exact command.

## Real-World Scenarios

### Scenario 1: Testing File Upload Feature

You're testing a document management system where users upload files through the UI.

```
Test: "Upload document and verify processing"

Prepare Test File:
1. Navigate to {{variable:APP_URL}}/documents
2. Wait until: Upload page loads

Upload via UI:
3. Click "Upload Document" button
4. Set file to upload: "test-document.pdf"
5. Input text: "Q4 Report" in title field
6. Click "Upload" button
7. Wait until: Upload completes

Verify Upload via API:
8. Execute the cURL command called VERIFY_DOCUMENT_UPLOADED
9. Extract information about document ID from response with key DOC_ID
10. Extract information about file size from response with key FILE_SIZE
11. Extract information about upload status from response with key UPLOAD_STATUS

Validate Results:
12. Assert: Upload status {{key:UPLOAD_STATUS}} is "complete"
13. Assert: Document ID {{key:DOC_ID}} is displayed in UI
14. Assert: File size {{key:FILE_SIZE}} matches uploaded file
```

**Why cURL is perfect here**: File uploads typically use multipart/form-data, which cURL handles natively with the `-F` flag. The stored cURL command might be:

```bash
curl -X POST https://api.example.com/documents \
  -H "Authorization: Bearer {{variable:AUTH_TOKEN}}" \
  -F "file=@{{variable:TEST_FILE_PATH}}" \
  -F "title={{key:DOC_TITLE}}"
```

### Scenario 2: Certificate-Based Authentication

Testing an enterprise API that requires client certificates for authentication.

```
Test: "Access secure API endpoint with certificates"

Authenticate via Certificate:
1. Execute the cURL command called AUTH_WITH_CERTIFICATE
2. Extract information about session token from response with key SESSION_TOKEN
3. Assert: Session token {{key:SESSION_TOKEN}} is not empty

Access Protected Resource:
4. Execute the cURL command called GET_PROTECTED_DATA
5. Extract information about user permissions from response with key PERMISSIONS
6. Assert: Permissions include "read", "write"

Test in UI:
7. Navigate to {{variable:APP_URL}}/dashboard
8. Wait until: Dashboard loads
9. Assert: Protected data is displayed correctly
10. Assert: User has appropriate access level
```

**Why cURL is perfect here**: Client certificate authentication requires specific cURL flags that aren't available in standard Fetch:

```bash
curl -X GET https://api.example.com/secure \
  --cert client.pem:{{variable:CERT_PASSWORD}} \
  --key client.key \
  -H "Accept: application/json"
```

### Scenario 3: Debugging API Integration Issues

Your application's API calls are failing intermittently, and you need detailed debugging information.

```
Test: "Debug checkout API integration"

Enable Verbose Logging:
1. Execute the cURL command called CHECKOUT_WITH_DEBUG
2. Extract information about request headers from verbose output with key REQUEST_HEADERS
3. Extract information about response headers from verbose output with key RESPONSE_HEADERS
4. Extract information about response time from output with key RESPONSE_TIME

Analyze Response:
5. Assert: Response time {{key:RESPONSE_TIME}} is less than 2000ms
6. Extract information about response status from output with key STATUS_CODE
7. Assert: Status code {{key:STATUS_CODE}} is 200 or 201

Verify in UI:
8. Navigate to order confirmation
9. Assert: Order was processed successfully
```

**Why cURL is perfect here**: The `-v` (verbose) flag provides detailed debugging information:

```bash
curl -X POST https://api.example.com/checkout \
  -H "Authorization: Bearer {{variable:AUTH_TOKEN}}" \
  -H "Content-Type: application/json" \
  -d '{"cart_id": "{{key:CART_ID}}"}' \
  -v \
  -w "\nResponse time: %{time_total}s\n"
```

The verbose output shows:
- Exact headers sent
- SSL handshake details
- Redirect information
- Timing breakdown
- Response headers received

**Why cURL is perfect here**: You need to make rapid-fire requests and capture specific response headers:

The `-i` flag includes headers in output, and `--max-time` and `--retry` give fine control over request behavior.

**Why cURL is perfect here**: cURL can save downloaded content and extract response headers:

```bash
curl -X GET https://api.example.com/reports/{{key:REPORT_ID}}/download \

```

The `-o` flag saves the file, `-w` formats output data, and `-D` dumps headers.

## Setting Up cURL Scripts

Before using cURL in your tests, configure your scripts in Autonoma.

### Basic cURL Script Structure

```bash
curl -X [METHOD] [URL] \
  -H "Header-Name: Header-Value" \
  -d 'request body' \
  [additional flags]
```

### Common cURL Flags and Options

**Request method:**
```bash
-X GET     # GET request (default)
-X POST    # POST request
-X PUT     # PUT request
-X PATCH   # PATCH request
-X DELETE  # DELETE request
```

**Headers:**
```bash
-H "Authorization: Bearer token"
-H "Content-Type: application/json"
-H "Accept: application/json"
-H "User-Agent: Autonoma-Test/1.0"
```

**Request body:**
```bash
-d '{"key":"value"}'           # JSON data
-d @file.json                   # Data from file
-F "field=value"                # Form field
-F "file=@document.pdf"         # File upload
```

**Authentication:**
```bash
-u username:password            # Basic auth
--cert client.pem              # Client certificate
--key client.key               # Private key
-H "Authorization: Bearer token" # Token auth
```

**Output control:**
```bash
-o filename                     # Save output to file
-O                              # Save with remote filename
-i                              # Include headers in output
-I                              # Show headers only
-v                              # Verbose output
-s                              # Silent mode
-S                              # Show errors in silent mode
```

**Connection control:**
```bash
--max-time 30                   # Timeout after 30 seconds
--connect-timeout 10            # Connection timeout
--retry 3                       # Retry 3 times on failure
--retry-delay 2                 # Wait 2 seconds between retries
```

**Cookie handling:**
```bash
-b cookies.txt                  # Send cookies from file
-c cookies.txt                  # Save cookies to file
-b "name=value"                 # Send specific cookie
```

**Redirect handling:**
```bash
-L                              # Follow redirects
--max-redirs 5                  # Maximum redirects to follow
```

**Custom options:**
```bash
-A "User-Agent string"          # Custom user agent
-e "https://referrer.com"       # Set referrer
--compressed                    # Request compressed response
```

### Using Variables in cURL Scripts

Make your cURL scripts flexible with Autonoma variables:

```bash
curl -X GET {{variable:API_BASE_URL}}/users/{{key:USER_ID}} \
  -H "Authorization: Bearer {{variable:AUTH_TOKEN}}" \
  -H "Accept: application/json"
```

**Variable types:**
- `{{variable:NAME}}` - Set before test runs (configuration)
- `{{key:NAME}}` - Extracted during test execution (dynamic data)
- `{{random:type}}` - Generated by Autonoma (test data)

### Common cURL Script Patterns

**GET request with authentication:**
```bash
curl -X GET {{variable:API_URL}}/profile \
  -H "Authorization: Bearer {{variable:AUTH_TOKEN}}" \
  -H "Accept: application/json"
```

**POST request with JSON:**
```bash
curl -X POST {{variable:API_URL}}/orders \
  -H "Authorization: Bearer {{variable:AUTH_TOKEN}}" \
  -H "Content-Type: application/json" \
  -d '{
    "customer_id": "{{key:CUSTOMER_ID}}",
    "items": [
      {"product_id": "{{key:PRODUCT_ID}}", "quantity": 1}
    ]
  }'
```

**File upload:**
```bash
curl -X POST {{variable:API_URL}}/documents \
  -H "Authorization: Bearer {{variable:AUTH_TOKEN}}" \
  -F "file=@{{variable:TEST_FILE}}" \
  -F "title={{key:DOC_TITLE}}" \
  -F "tags={{key:DOC_TAGS}}"
```

**PUT with data from file:**
```bash
curl -X PUT {{variable:API_URL}}/resources/{{key:RESOURCE_ID}} \
  -H "Authorization: Bearer {{variable:AUTH_TOKEN}}" \
  -H "Content-Type: application/json" \
  -d @update_data.json
```

**DELETE with confirmation:**
```bash
curl -X DELETE {{variable:API_URL}}/items/{{key:ITEM_ID}} \
  -H "Authorization: Bearer {{variable:AUTH_TOKEN}}" \
  -H "X-Confirm: true"
```

**Certificate-based authentication:**
```bash
curl -X GET {{variable:API_URL}}/secure/data \
  --cert {{variable:CERT_PATH}} \
  --key {{variable:KEY_PATH}} \
  -H "Accept: application/json"
```

**Verbose debugging:**
```bash
curl -X POST {{variable:API_URL}}/transaction \
  -H "Authorization: Bearer {{variable:AUTH_TOKEN}}" \
  -H "Content-Type: application/json" \
  -d '{"amount": {{key:AMOUNT}}}' \
  -v \
  -w "\nHTTP Code: %{http_code}\nTime: %{time_total}s\n"
```

## Best Practices

### 1. Use Descriptive Script Names

**Poor naming:**
```
CURL_1
CURL_2
API_TEST
CURL_COMMAND
```

**Good naming:**
```
UPLOAD_PDF_WITH_METADATA
GET_USER_WITH_CERTIFICATE
DEBUG_CHECKOUT_VERBOSE
VERIFY_WEBHOOK_DELIVERY
DOWNLOAD_MONTHLY_REPORT
```

### 2. Store Complex cURL Commands

If a cURL command is long or complex, store it rather than recreate it:

**Instead of:**
```
Rewriting a 10-line cURL command in every test
```

**Do this:**
```
Store once as "UPLOAD_DOCUMENT_FULL"
Use in all tests with:
"execute the cURL command called UPLOAD_DOCUMENT_FULL"
```

### 3. Use Variables for Flexibility

Make cURL scripts work across environments:

```bash
curl -X GET {{variable:API_BASE_URL}}/data \
  -H "Authorization: Bearer {{variable:AUTH_TOKEN}}" \
  --cert {{variable:CERT_PATH}} \
  --max-time {{variable:API_TIMEOUT}}
```

Configure variables per environment:
- **Development**: Fast timeouts, local certificates
- **Staging**: Longer timeouts, staging certificates
- **Production**: Production timeouts and certificates

### 4. Include Error Handling

Use cURL flags that help with error scenarios:

```bash
curl -X POST {{variable:API_URL}}/order \
  -H "Authorization: Bearer {{variable:AUTH_TOKEN}}" \
  -d '{"items": [{{key:CART_ITEMS}}]}' \
  --max-time 30 \
  --retry 3 \
  --retry-delay 2 \
  -f \
  -S
```

Flags explained:
- `--max-time 30`: Fail if request takes over 30 seconds
- `--retry 3`: Retry up to 3 times on failure
- `--retry-delay 2`: Wait 2 seconds between retries
- `-f`: Fail silently on HTTP errors
- `-S`: Show errors even in silent mode

### 5. Use Verbose Mode for Debugging

When creating or debugging cURL scripts, use verbose output:

```bash
curl -X POST {{variable:API_URL}}/endpoint \
  -H "Authorization: Bearer {{variable:AUTH_TOKEN}}" \
  -d '{"data": "value"}' \
  -v
```

Remove `-v` once the script works correctly to reduce output noise.

### 6. Handle File Paths Properly

When uploading files, use absolute paths or variables:

```bash
# Good: Using variable
-F "file=@{{variable:TEST_FILE_PATH}}"

# Good: Absolute path
-F "file=@/path/to/test-files/document.pdf"

# Risky: Relative path (depends on working directory)
-F "file=@./document.pdf"
```

### 7. Extract and Verify Responses

Always capture and validate cURL responses:

```
1. Execute the cURL command called CREATE_ORDER
2. Extract information about order ID from response with key ORDER_ID
3. Extract information about status code from response with key STATUS
4. Assert: Status {{key:STATUS}} is 201
5. Assert: Order ID {{key:ORDER_ID}} exists
```

## Common Pitfalls

### Pitfall 1: Not Escaping Special Characters

**Problem:**
```bash
curl -X POST https://api.example.com/data \
  -d '{"message": "Don't forget"}' # Single quote breaks the command
```

**Solution:**
```bash
curl -X POST https://api.example.com/data \
  -d '{"message": "Don'\''t forget"}' # Escape the quote

# Or use double quotes:
curl -X POST https://api.example.com/data \
  -d "{\"message\": \"Don't forget\"}"
```

### Pitfall 2: Hardcoding Environment-Specific Values

**Problem:**
```bash
curl -X GET https://staging-api.example.com/users \
  -H "Authorization: Bearer abc123token"
```

This only works in staging with that specific token.

**Solution:**
```bash
curl -X GET {{variable:API_BASE_URL}}/users \
  -H "Authorization: Bearer {{variable:AUTH_TOKEN}}"
```

### Pitfall 3: Not Handling Timeouts

**Problem:**
```bash
curl -X POST https://api.example.com/long-process \
  -d '{"data": "value"}'
```

If the API is slow, this might hang indefinitely.

**Solution:**
```bash
curl -X POST https://api.example.com/long-process \
  -d '{"data": "value"}' \
  --max-time 60 \
  --connect-timeout 10
```

### Pitfall 4: Ignoring Response Status Codes

**Problem:**
```
1. Execute the cURL command called UPDATE_PROFILE
2. Navigate to profile page
3. Assume update succeeded
```

The API might have returned an error.

**Solution:**
```
1. Execute the cURL command called UPDATE_PROFILE
2. Extract information about HTTP status from response with key STATUS_CODE
3. Assert: Status code {{key:STATUS_CODE}} is 200
4. Navigate to profile page
5. Verify changes applied
```

### Pitfall 5: Not Testing cURL Scripts Independently

**Problem:**
```
Creating complex cURL scripts and only testing them within full test flows
```

**Solution:**
```
Test cURL scripts independently first:
1. Execute the cURL command called NEW_SCRIPT
2. Extract and verify response
3. Confirm it works as expected

Then integrate into full test flows
```

### Pitfall 6: Overly Complex Single Commands

**Problem:**
```bash
curl -X POST https://api.example.com/complex \
  -H "Header1: value" \
  -H "Header2: value" \
  -H "Header3: value" \
  -d '{"huge": "json", "with": "many", "nested": {"objects": "values"}}' \
  --cert cert.pem --key key.pem \
  -v -L --retry 3 --retry-delay 2 --max-time 30 \
  -w "Status: %{http_code}\n"
```

This is hard to read and maintain.

**Solution:**
Break into multiple scripts:
- `AUTH_WITH_CERT`: Handle certificate authentication
- `POST_COMPLEX_DATA`: Post the data
- `DEBUG_RESPONSE`: Debug version with verbose output

Or store data in a file:
```bash
curl -X POST https://api.example.com/complex \
  -H "Authorization: Bearer {{variable:TOKEN}}" \
  -d @complex_data.json
```

```
Test: "API response time under load"

3. Assert: Response time {{key:BASELINE_TIME}} is less than 500ms
```


### Pattern 4: Webhook Testing End-to-End


## Debugging cURL Issues

### Issue: Command Syntax Error

**Error message:**
```
cURL command failed: syntax error near unexpected token
```

**Common causes:**
- Unescaped special characters
- Unclosed quotes
- Invalid JSON in request body

**Solution:**
```bash
# Check for:
1. Matching quotes: '...' or "..."
2. Escaped special characters: \' or \"
3. Valid JSON: Use a JSON validator
4. Proper line continuations: \

# Test the command manually first:
curl -X POST https://api.example.com/test \
  -H "Content-Type: application/json" \
  -d '{"valid": "json"}'
```

### Issue: SSL Certificate Problems

**Error message:**
```
SSL certificate problem: unable to get local issuer certificate
```

**Common causes:**
- Self-signed certificates
- Certificate chain issues
- Missing CA certificates

**Solution:**
```bash
# For testing only (not production):
curl -X GET https://api.example.com/endpoint \
  -k  # or --insecure to bypass certificate validation

# Proper solution:
curl -X GET https://api.example.com/endpoint \
  --cacert ca-bundle.crt  # Specify CA certificate
```

### Issue: Authentication Failed

**Error message:**
```
HTTP 401 Unauthorized
```

**Common causes:**
- Token expired or invalid
- Wrong authentication method
- Missing authorization header

**Solution:**
```bash
# Verify token is correct:
echo "{{variable:AUTH_TOKEN}}"  # Check token value

# Test authentication:
curl -X GET https://api.example.com/protected \
  -H "Authorization: Bearer {{variable:AUTH_TOKEN}}" \
  -v  # Verbose mode shows auth headers sent

# Check response headers:
curl -X GET https://api.example.com/protected \
  -H "Authorization: Bearer {{variable:AUTH_TOKEN}}" \
  -i  # Include response headers
```

### Issue: Request Timeout

**Error message:**
```
Operation timed out after 30000 milliseconds
```

**Common causes:**
- API endpoint is slow or unresponsive
- Network connectivity issues
- Too short timeout setting

**Solution:**
```bash
# Increase timeout:
curl -X GET https://api.example.com/slow \
  --max-time 120  # 120 seconds timeout

# Test connectivity:
curl -X GET https://api.example.com/health \
  --connect-timeout 5 \
  -v

# Add retry logic:
curl -X GET https://api.example.com/endpoint \
  --max-time 30 \
  --retry 3 \
  --retry-delay 5
```
