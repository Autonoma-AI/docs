## What is Backspace?

Backspace is an interaction that simulates pressing the backspace key on your keyboard to delete characters from an input field. It works just like the real backspace key—removing one character at a time from the right side of the text (or from the cursor position if the cursor isn't at the end).

Think of it as the "undo" for text input—when you need to remove characters, correct typos, or clear a field partially, Backspace is your tool.

## When to Use Backspace

Backspace is useful in scenarios where you need to delete or edit existing text:

### Scenario 1: Correcting Typos

You've typed something wrong and need to fix it:

```
Step 1: input tom@autanoma.app on the email field  // Typo: "autanoma"
Step 2: Backspace 12 times  // Delete the wrong domain
Step 3: input autonoma.app on the email field
```

### Scenario 2: Editing Pre-Filled Fields

Fields that come with default values you need to change:

```
Step 1: Click the phone number field  // Pre-filled with (555) 000-0000
Step 2: Backspace 20 times  // Clear the entire field
Step 3: input 4155551234 on the phone number field
```

### Scenario 3: Partial Deletions

Removing just part of the text:

```
Step 1: input John Smith on the name field
Step 2: Backspace 5 times  // Removes "Smith"
Step 3: input Doe on the name field  // Now it's "John Doe"
```

### Scenario 4: Testing Character Limits

Verifying that fields enforce maximum lengths:

```
Step 1: input ABCDEFGHIJKLMNOP on the field  // 16 characters
Step 2: Verify the field contains only ABCDEFGHIJ  // Field limited to 10
Step 3: Backspace 2 times
Step 4: input YZ on the field
```

### Scenario 5: Clear and Re-Enter

Completely clearing a field before entering new data:

```
Step 1: Click the search field  // Has previous search query
Step 2: Backspace 50 times  // Clear everything (even if less than 50 chars)
Step 3: input new search query on the search field
```

### Scenario 6: Testing Validation on Deletion

Verifying that validation updates when content is removed:

```
Step 1: input test@example.com on the email field
Step 2: Verify the checkmark appears
Step 3: Backspace 15 times  // Remove "@example.com"
Step 4: Verify the error message appears
```

### When NOT to Use Backspace

Don't use Backspace when:

- **Input Text will clear the field**: By default, Input Text clears existing content
- **You want to clear everything**: Use a clear button or select-all + delete instead
- **The field is empty**: Nothing to delete
- **You can just re-input**: Input Text overwrites in most cases

## How It Works

Backspace has simple execution logic:

1. **Requires focus**: An input field must be focused
2. **Deletes characters**: Removes characters one at a time from the cursor position
3. **Repeats**: Can be executed multiple times in one action
4. **Direction**: Deletes from right to left (backward)

### Default Behavior

If you don't specify a count, Backspace deletes **1 character**:

```
Backspace  // Deletes 1 character
```

### Specifying Count

You can delete multiple characters at once:

```
Backspace 5 times  // Deletes 5 characters
Backspace 10  // Deletes 10 characters
```

### What Happens Behind the Scenes

```
Field content: "Hello World"
Cursor position: End of text

Action: Backspace 5 times

Result:
Step 1: "Hello Worl"  (deleted "d")
Step 2: "Hello Wor"   (deleted "l")
Step 3: "Hello Wo"    (deleted "r")
Step 4: "Hello W"     (deleted "o")
Step 5: "Hello "      (deleted "W")
```

## Platform Support

- **Web**: Fully supported
- **Mobile**: Fully supported

Backspace works consistently across both platforms, though mobile might show on-screen backspace buttons on keyboards.

## Understanding Metadata

The metadata for Backspace is the **number of times** to press backspace:

**Prompt**: `backspace`
**Metadata**: `1` (default)

**Prompt**: `backspace 5 times`
**Metadata**: `5`

**Prompt**: `backspace 10`
**Metadata**: `10`

The metadata is always a number—how many characters to delete.

## Best Practices

### 1. Ensure Field is Focused

Backspace only works on focused fields:

**Good**:
```
Step 1: Click the email field
Step 2: Backspace 5 times
```

Or:
```
Step 1: input text on the field  // This focuses the field
Step 2: Backspace 5 times
```

**Bad**:
```
Step 1: Verify the form is visible
Step 2: Backspace 5 times  // Nothing is focused!
```

### 2. Use Generously When Clearing

When you're not sure of the exact length, use a high count:

```
Backspace 100 times  // Will delete everything, even if field has 20 chars
```

The backspace stops when the field is empty—it won't cause errors if you backspace more than available characters.

### 3. Verify After Deletion

Confirm that the right content was deleted:

```
Step 1: input Hello World on the field
Step 2: Backspace 6 times  // Should delete " World"
Step 3: Verify the field contains Hello
```

### 4. Calculate Character Count Correctly

Count carefully when deleting specific portions:

```
Text: "john.smith@example.com"
To delete "@example.com": 12 characters
Command: Backspace 12 times
```

**Tip**: Use a text editor to count characters if you're unsure.

### 5. Consider Input Text Instead

Often, Input Text is simpler because it clears the field automatically:

**With Backspace**:
```
Step 1: Click the field
Step 2: Backspace 50 times
Step 3: input new value on the field
```

**With Input Text only**:
```
Step 1: input new value on the field  // Input Text clears automatically
```

The second approach is simpler and more reliable.

### 6. Test Edge Cases

Verify backspace behavior at boundaries:

```
// Test: Backspace on empty field (should do nothing)
Step 1: Click the empty field
Step 2: Backspace 5 times
Step 3: Verify the field is still empty

// Test: Backspace more than available characters
Step 1: input Hi on the field
Step 2: Backspace 10 times  // Only 2 chars available
Step 3: Verify the field is empty
```

### 7. Use with Verification for Validation Testing

Test that validation responds to deletion:

```
Step 1: input valid@email.com on the email field
Step 2: Verify I see the success icon
Step 3: Backspace 4 times  // Delete ".com"
Step 4: Verify I see the error message
```

## Common Pitfalls

### Pitfall 1: No Field is Focused

**Problem**: Backspace does nothing because no field has focus.

**Example**:
```
Step 1: Verify the form exists
Step 2: Backspace 5 times  // Fails - nothing focused
```

**Solution**: Focus the field first:
```
Step 1: Click the field
Step 2: Backspace 5 times
```

### Pitfall 2: Wrong Character Count

**Problem**: You calculate the wrong number of characters to delete.

**Example**: Trying to delete "example.com" (11 chars) but using `Backspace 10 times`

**Solution**: Count carefully or use a generous count:
```
Backspace 15 times  // Ensures everything is deleted
```

### Pitfall 3: Using When Input Text Would Work

**Problem**: Overcomplicating with Backspace when Input Text clears automatically.

**Overcomplicated**:
```
Step 1: Click the field with pre-filled text
Step 2: Backspace 50 times
Step 3: input new text on the field
```

**Simpler**:
```
Step 1: input new text on the field  // Automatically clears old text
```

**When to use Backspace**: Only when you need to partially delete or test deletion functionality.

### Pitfall 4: Backspacing on Non-Editable Fields

**Problem**: Trying to backspace on read-only or disabled fields.

**Example**:
```
Step 1: Click the read-only field
Step 2: Backspace 5 times  // Won't work - field is read-only
```

**Solution**: Verify the field is editable first, or don't use Backspace.

### Pitfall 5: Cursor Position Confusion

**Problem**: Cursor is in the middle of text, not at the end.

**Example**:
```
Text: "Hello World"
Cursor: Between "Hello" and "World"
Action: Backspace 5 times
Result: "World" (deleted "Hello ")
```

**Solution**: Be aware of cursor position, or click at the end of the field first.

### Pitfall 6: Not Verifying Deletion

**Problem**: Assuming deletion worked without checking.

**Example**:
```
Step 1: Backspace 10 times
Step 2: input new text  // What if deletion failed?
```

**Solution**: Verify deletion:
```
Step 1: Backspace 10 times
Step 2: Verify the field is empty
Step 3: input new text
```

### Pitfall 7: Mobile Keyboard Behavior

**Problem**: On mobile, keyboard might close between steps.

**Example**:
```
Step 1: input text on mobile field
Step 2: Click outside the field  // Keyboard closes
Step 3: Backspace 5 times  // Keyboard is gone, field not focused
```

**Solution**: Keep field focused:
```
Step 1: input text on mobile field
Step 2: Backspace 5 times  // Immediately, while field is focused
Step 3: input more text
```

## Debugging Backspace Issues

### Issue: Backspace Does Nothing

**Debugging steps**:
1. Verify a field is focused
2. Check if the field is editable (not read-only/disabled)
3. Verify there's content to delete
4. Try clicking the field before backspace

### Issue: Wrong Amount Deleted

**Debugging steps**:
1. Count the characters manually
2. Verify cursor position (might be in middle of text)
3. Check if field has hidden characters (spaces, line breaks)
4. Use a higher count to ensure complete deletion

### Issue: Backspace Works Manually but Not in Test

**Debugging steps**:
1. Add wait time before backspace
2. Verify field has focus in test playback
3. Check for JavaScript interference
4. Try clicking the field immediately before backspace

### Issue: Field Doesn't Update After Backspace

**Debugging steps**:
1. Verify the field isn't read-only
2. Check for JavaScript preventing changes
3. Try typing after backspace to ensure focus
4. Check browser console for errors

## Key Takeaways

1. **Backspace deletes characters** from the cursor position (usually end of text)
2. **Works on both Web and Mobile** platforms
3. **Requires focused field** to work
4. **Default is 1 character**, but you can specify more: `Backspace 10 times`
5. **Use generously when clearing**—high counts won't cause errors
6. **Often Input Text is simpler**—it clears automatically when re-inputting
7. **Verify deletion** to ensure the right content was removed
8. **Count characters carefully** when deleting specific portions
9. **Stops at empty**—won't error if you backspace more than available characters
10. **Useful for testing validation, character limits, and editing workflows**

## Related Interactions

- **Input Text**: Type text into fields (automatically clears existing content)
- **Input on Focus**: Type into focused field without locating it
- **Click**: Focus a field before using Backspace
- **Keypad**: Enter numbers on mobile (combine with Backspace for corrections)
- **Send Enter**: Submit after editing with Backspace

## Decision Framework

When deciding whether to use Backspace:

```
Need to modify field content?
│
├─ Replace entire content?
│  └─ Use Input Text (it clears automatically)
│
├─ Delete specific portion?
│  └─ Use Backspace (calculate character count)
│
├─ Clear pre-filled default?
│  ├─ Input Text won't clear it? → Use Backspace
│  └─ Input Text will clear it? → Use Input Text
│
├─ Test deletion functionality?
│  └─ Use Backspace (with verification)
│
└─ Edit in the middle of text?
   └─ Use Backspace (be aware of cursor position)
```
