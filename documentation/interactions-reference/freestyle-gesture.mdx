## What is Freestyle Gesture?

Freestyle Gesture is a flexible interaction that allows you to drag from one location to another on the screen. Unlike structured drag-and-drop or specific swipe directions, Freestyle Gesture lets you specify any two points and create a custom drag path between them.

Think of it like drawing a line on the screen with your finger—you specify where to start and where to end, and Autonoma creates the drag gesture between those points. This makes it perfect for custom swipe gestures, drag-to-refresh actions, unlocking patterns, navigation swipes, and any interaction that requires moving from point A to point B.

Freestyle Gesture is particularly powerful on mobile where swipe gestures are common, but it can also be used on web for drag-based interactions.

## When to Use Freestyle Gesture

Freestyle Gesture is designed for drag-based interactions with specific start and end points.

**Use Freestyle Gesture when:**
- Swiping from one edge to another (e.g., swipe from left edge to open menu)
- Drag-to-refresh gestures (drag from top downward)
- Custom swipe navigation (swipe from right to left to go to next screen)
- Unlock patterns or swipe-to-unlock gestures
- Dismissing items by dragging (swipe item left to delete)
- Page turning gestures (drag corner to turn page)
- Drawing or tracing interactions
- Any gesture requiring specific start and end coordinates

**Don't use Freestyle Gesture when:**
- Standard click or tap works (use Click)
- Structured drag-and-drop between elements (use drag-and-drop interaction)
- Scrolling (use scroll interaction)
- Pinch-to-zoom (use zoom interaction)
- You need complex multi-touch gestures
- Single-point interactions are sufficient

## How It Works

Freestyle Gesture creates a drag path between two points:

1. **Start Point Detection**: Identifies the starting location
2. **End Point Detection**: Identifies the ending location
3. **Path Calculation**: Determines the drag path between points
4. **Touch Down**: Initiates contact at start point
5. **Drag Motion**: Moves along calculated path
6. **Touch Up**: Releases at end point
7. **Gesture Recognition**: UI responds to the gesture

The system handles the smooth motion between your specified start and end points, creating a natural drag gesture.

## Platform Support

- **Web**: Not mentioned (primarily for advanced interactions)
- **Mobile**: Full support

Freestyle Gesture is primarily designed for mobile touch interactions, though it may work on web for drag-based interfaces.

## Example Prompts

Freestyle Gesture uses "drag from... to..." language:

**Edge to center:**
```
drag from the left edge to the center
drag from the top left corner to the bottom right corner
drag from the right edge to the middle
```

**Directional drags:**
```
drag from the top of the screen downward
drag from right to left
drag from bottom to top
```

**Element-based drags:**
```
drag from the whatsapp icon to the top right corner
drag from the first item to the left
drag the notification from left to right
```

**Carousel/component drags:**
```
drag from the left of the carousel to the right of the carousel
drag from the bottom of the list to the top
drag from the profile icon to the settings area
```

**Important**: Must specify two locations—start (from) and end (to). The prompt needs both points.

## Best Practices

### 1. Always Specify Two Locations

Freestyle Gesture requires both start and end points.

**Good:**
```
drag from the left edge to the center
drag from the top of the screen to the middle
drag from the icon to the trash
```

**Incomplete:**
```
drag from the left  ← Missing end point
swipe down  ← Need specific start and end
```

### 2. Use Clear Positional References

Help the system identify exactly where to start and end.

**Good:**
```
drag from the top left corner to the bottom right corner
drag from the left edge of the screen to the center
drag from the notification to the right side
```

**Vague:**
```
drag from here to there
swipe over
move it
```

### 3. Consider Gesture Direction and Distance

Think about what the gesture needs to accomplish.

**For swipe navigation:**
```
drag from right to left  ← Moves content to the left, showing what's on the right
```

**For pull-to-refresh:**
```
drag from the top downward  ← Pulls content down to trigger refresh
```

**For menu reveal:**
```
drag from the left edge to the center  ← Opens left-side menu
```

### 4. Wait for Gesture Results

Allow time for animations and responses.

**Good:**
```
1. drag from left edge to center
2. Wait until: Menu animation completes
3. Verify: Menu is visible
4. Interact with menu
```

**Risky:**
```
1. drag from left edge to center
2. Immediately click menu item  ← Menu might still be animating
```

### 5. Verify Gesture Succeeded

Confirm the gesture produced the expected result.

**Good:**
```
1. drag from top downward for refresh
2. Wait until: Refresh indicator appears
3. Wait until: Content reloads
4. Verify: New content is present
```

## Common Pitfalls

### Pitfall 1: Not Specifying Both Points

**Problem:**
```
drag from the left
# Missing endpoint—where should it drag to?
```

**Solution:**
```
drag from the left edge to the center of the screen
# Clear start and end points
```

### Pitfall 2: Using for Non-Drag Interactions

**Problem:**
```
Using Freestyle Gesture for standard button clicks
```

**Solution:**
```
Use Click for taps and clicks
Use Freestyle Gesture only for actual drag movements
```

### Pitfall 3: Vague Position References

**Problem:**
```
drag from there to over there
# System can't determine locations
```

**Solution:**
```
drag from the top left corner to the bottom right corner
# Specific, identifiable positions
```

### Pitfall 4: Not Accounting for Gesture Distance

**Problem:**
```
drag from top to almost top
# Distance too short to trigger gesture
```

**Solution:**
```
Ensure drag distance is sufficient
Test that gesture distance meets UI threshold
Drag far enough to trigger the action
```

### Pitfall 5: Ignoring Animation Timing

**Problem:**
```
1. drag to open menu
2. Click menu item  ← Menu might still be sliding in
```

**Solution:**
```
1. drag to open menu
2. Wait until: Menu fully opens
3. Click menu item
```

## Comparison with Similar Interactions

### Freestyle Gesture vs Click

**Click:**
- Action: Single tap at point
- Movement: None
- Best for: Activating elements
- Use case: 95% of interactions

**Freestyle Gesture:**
- Action: Drag from point A to point B
- Movement: Path between two points
- Best for: Swipe gestures, custom drags
- Use case: Gesture-based navigation

**Decision rule**: Use Click for taps. Use Freestyle Gesture for drag movements.

### Freestyle Gesture vs Scroll

**Freestyle Gesture:**
- Purpose: Specific gesture interaction
- Control: Precise start and end points
- Best for: Swipes, reveals, custom gestures
- Example: Swipe to open menu

**Scroll:**
- Purpose: Content navigation
- Control: Scroll direction and amount
- Best for: Viewing content beyond viewport
- Example: Scroll down to see more items

**Different purposes**: Freestyle Gesture is for gesture interactions. Scroll is for content navigation.

### Freestyle Gesture vs Drag-and-Drop

**Freestyle Gesture:**
- Level: Coordinate-based
- Specification: Start and end positions
- Best for: Gesture interactions, swipes
- Example: Drag from left edge to center

**Drag-and-Drop:**
- Level: Element-based
- Specification: Source and target elements
- Best for: Moving items between containers
- Example: Drag file to folder

**Different abstractions**: Freestyle Gesture uses positions. Drag-and-drop uses elements.

```

Mix gestures with other interactions:

```

Same gesture in different contexts:

```

```

## Mobile-Specific Considerations

Freestyle Gesture is particularly powerful on mobile:

### Mobile Navigation Patterns

```
Test: "Standard mobile gestures"

Back gesture:
- drag from left edge to right  ← Go back

Menu reveal:
- drag from left edge to center  ← Open menu

Screen transition:
- drag from right to left  ← Next screen
- drag from left to right  ← Previous screen

Pull to refresh:
- drag from top downward  ← Refresh content
```

### Swipe Threshold

Mobile gestures often have distance thresholds:

```
Understanding:
- Short swipe might not trigger action
- Gesture needs sufficient distance
- Test to determine minimum drag distance

In tests:
- Use adequate drag distances
- "from edge to center" usually sufficient
- "from right to left" across substantial area
```

### Gesture Speed

Some gestures are speed-sensitive:

```
Fast swipe (flick):
- May scroll further or trigger different action
- Freestyle Gesture performs standard-speed drag

Slow drag:
- More controlled
- May trigger different features (like peek)

Most cases: Standard drag speed works
```

## Key Takeaways

1. **Freestyle Gesture is for drags** - From one point to another
2. **Two locations required** - Must specify start (from) and end (to)
3. **Mobile primary** - Designed for mobile touch gestures
4. **Clear positions** - Use specific location references
5. **Various uses** - Swipes, reveals, navigation, refresh
6. **Wait for animations** - Allow gestures to complete
7. **Verify results** - Confirm gesture achieved goal
8. **Direction matters** - Left-to-right vs right-to-left have different meanings

10. **Not for scrolling** - Use scroll interaction for content navigation
