## What is OCR Hover?

OCR Hover uses optical character recognition (OCR) to identify text visually on the screen and then hovers the mouse over that element. Unlike standard hover interactions that rely on the DOM structure, OCR Hover looks at what's actually visible on screen—just like a human would—and positions the mouse over it.

Think of it as teaching your test to "read" the screen and hover over what it sees, rather than relying on HTML elements. This is particularly powerful for situations where standard DOM-based interactions fail because elements aren't properly structured or accessible.

This interaction is valuable for:
- Hovering over canvas-rendered elements
- Testing hover states on images containing text
- Interacting with elements lacking proper accessibility attributes
- Testing applications using non-standard rendering
- Validating hover behavior on dynamically generated visuals
- Testing third-party components with limited DOM access

## The OCR Hover Use Case

Modern web applications increasingly use rendering technologies that bypass traditional DOM structures:

**Canvas-Based Applications**
```
Drawing tools and image editors
Data visualizations rendered on canvas
Games and interactive graphics
Charts that don't use SVG or HTML elements
```

**Image-Based Interfaces**
```
Scanned documents with interactive regions
Image maps without proper HTML areas
Screenshots with clickable elements
Visual mockups that became functional
```

**Third-Party Components**
```
Embedded widgets with shadow DOM
IFrames with limited access
Proprietary components with hidden structure
Legacy applications wrapped in modern shells
```

**Accessibility Issues**
```
Elements missing proper ARIA labels
Interactive elements without text content
Buttons rendered as background images
Clickable regions without semantic markup
```

**Standard hover fails** when:
- Element isn't in the accessible DOM
- Element lacks text content or labels
- Element is part of a canvas rendering
- Element is within an inaccessible iframe

**OCR Hover succeeds** because:
- It sees what's actually rendered
- It reads visible text using OCR
- It doesn't require DOM structure
- It works like a human using visual cues

## When to Use OCR Hover

### Use OCR Hover when:

**Standard hover doesn't work**
```
You've tried regular hover and it fails
Element exists visually but not in DOM
No appropriate selector available
```

**Canvas-based elements**
```
Buttons rendered on HTML5 canvas
Interactive charts using canvas
Drawing tools with text labels
Game UI elements
```

**Images with text**
```
Image-based navigation
Buttons that are images with text
Scanned documents with interactive regions
Infographics with clickable areas
```

**Third-party components**
```
Embedded widgets you can't inspect
Black-box components with limited API
Legacy systems with non-standard markup
```

**Missing accessibility attributes**
```
Elements without proper labels
Interactive elements lacking semantic HTML
Components built before accessibility standards
```

### Use standard hover when:

**Elements are properly in the DOM**
```
Standard buttons, links, and interactive elements
Elements with proper HTML structure
Components with accessible markup
```

**Performance is critical**
```
OCR has overhead compared to DOM-based hover
For speed, prefer standard interactions when possible
```

**Text might change**
```
If the visible text changes frequently
OCR-based identification might be inconsistent
Consider more stable selectors
```

## How It Works

When you use OCR Hover:

1. **Screenshot Capture**: Autonoma captures the current screen state
2. **OCR Processing**: Text recognition identifies visible text on screen
3. **Text Matching**: Your specified text is located in the OCR results
4. **Position Calculation**: Element position is determined from OCR coordinates
5. **Mouse Movement**: Mouse moves to hover over the identified element
6. **Hover State**: Hover state is triggered, potentially revealing tooltips or effects

## Platform Support

- **Web**: Full support
- **Mobile**: Full support (Android and iOS)

OCR Hover works across platforms because it relies on visual recognition rather than platform-specific APIs.

## Best Practices

### 1. Try Standard Hover First

OCR Hover should be a fallback, not the first choice:

```
# Try standard hover:
Hover on "Login" button

# If that fails:
OCR hover on "Login"
```

Standard hover is faster and more reliable when it works.

### 2. Use Specific Text for OCR

Be specific about the text to hover over:

**Vague:**
```
ocr hover on button
```

**Specific:**
```
ocr hover on "Submit Form"
```

**Very specific (if multiple similar texts):**
```
ocr hover on "Submit" button in footer
```

### 3. Wait After OCR Hover

Allow time for hover effects to appear:

```
1. OCR hover on "Products"
2. Wait 500ms for hover effect
3. Assert: Dropdown menu appears
4. Assert: Hover state is visible
```

### 4. Account for OCR Accuracy

OCR isn't perfect—use clear, distinct text:

**Good for OCR:**
```
ocr hover on "Settings"
ocr hover on "Login"
ocr hover on "Submit"
```

**Challenging for OCR:**
```
ocr hover on "|||" (icon without text)
ocr hover on "..." (ambiguous)
ocr hover on "1" (when many numbers present)
```

### 5. Test OCR Hover Consistency

OCR results can vary slightly:

```
Test multiple times:
1. OCR hover on "Dashboard"
2. Verify hover works
3. Hover away
4. OCR hover on "Dashboard" again
5. Verify still works consistently
```

### 6. Combine with Visual Assertions

Verify hover effects are visible:

```
1. OCR hover on "Chart"
2. Wait 500ms
3. Take screenshot
4. Assert: Tooltip is visible
5. Assert: Hover state styling applied
```

### 7. Document When OCR Hover is Necessary

Help future maintainers understand why OCR Hover is used:

```
# Using OCR hover because chart is canvas-based
1. OCR hover on "January" data label
2. Wait for tooltip

# Standard hover doesn't work on image buttons
3. OCR hover on "Products" image button
```

## Common Pitfalls

### Pitfall 1: Using OCR Hover When Standard Hover Works

**Problem:**
```
Using OCR hover for all hovers
Slower test execution
Unnecessary complexity
```

**Solution:**
```
1. Try standard hover first
2. Only use OCR hover when standard hover fails
3. Document why OCR hover is necessary
```

### Pitfall 2: Hovering on Ambiguous Text

**Problem:**
```
ocr hover on "1"
```

There might be many "1"s on the page (dates, counts, IDs, etc.)

**Solution:**
```
ocr hover on "January 1st"
ocr hover on "Product 1" in the product list
```

Be specific to avoid ambiguity.

### Pitfall 3: Not Waiting for Hover Effects

**Problem:**
```
1. OCR hover on "Menu"
2. Immediately click submenu item ← Submenu hasn't appeared yet!
```

**Solution:**
```
1. OCR hover on "Menu"
2. Wait 500ms for hover effect
3. Wait until: Submenu appears
4. Click submenu item
```

### Pitfall 4: OCR on Dynamic Text

**Problem:**
```
ocr hover on "Loading..."
```

Text changes to "Complete", OCR can't find "Loading..." anymore.

**Solution:**
```
1. Wait until: Loading completes
2. Wait until: Text changes to stable state
3. OCR hover on "Dashboard" (stable text)
```

### Pitfall 5: Expecting Perfect OCR Accuracy

**Problem:**
```
ocr hover on "Scttings" (expecting to find typo)
```

OCR might correct the typo or fail to find it.

**Solution:**
```
# Hover on the corrected text:
ocr hover on "Settings"

# Or be flexible with partial matches
```

### Pitfall 6: Not Testing OCR Hover Fallback

**Problem:**
```
Test assumes OCR hover always works
No fallback when OCR fails
```

**Solution:**
```
1. Try OCR hover on "Button"
2. If OCR fails:
3.   Try standard hover on button element
4.   Or try clicking directly
5. Assert: One method succeeded
```

## Debugging OCR Hover Issues

### Issue: OCR Can't Find Text

**Error:**
```
OCR hover failed: Text "Login" not found
```

**Possible causes:**
1. Text isn't visible on screen
2. Text is too small or blurry
3. Low contrast between text and background
4. Font is unusual and OCR can't recognize it

**Solutions:**
```
# Check text is visible:
Take screenshot and verify text appears

# Try different text:
If button says "Sign In" but you looked for "Login"

# Zoom in:
Zoom in to make text larger and clearer

# Verify contrast:
Ensure text has sufficient contrast
```

### Issue: Wrong Element Hovered

**Problem:**
```
Multiple elements have same text
OCR hovers on wrong one
```

**Solution:**
```
# Be more specific:
Instead of: ocr hover on "Submit"
Use: ocr hover on "Submit" button at bottom

# Or use position clues:
ocr hover on "Submit" in the checkout form

# Or use standard hover if possible:
If elements are in DOM, use regular hover with selector
```

### Issue: Hover Effect Not Appearing

**Problem:**
```
OCR hover executes but no hover effect shows
```

**Possible causes:**
1. Element doesn't have hover effect
2. Hover event not properly implemented
3. CSS hover doesn't work with programmatic hover
4. Need to wait longer for effect

**Solutions:**
```
# Wait longer:
1. OCR hover on element
2. Wait 1 second instead of 500ms

# Verify hover is implemented:
Check if element actually has hover styling

# Try different interaction:
If hover doesn't work, try clicking
```
