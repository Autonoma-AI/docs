## What is Click Until?

Click Until is a looping interaction that repeatedly clicks an element until a specified condition becomes true. Instead of clicking once, it keeps clicking until something specific happens—a certain value appears, specific content becomes visible, or a target state is reached.

Think of it like pressing an elevator button until you reach the right floor, or clicking "Next" in a slideshow until you see the slide you want. You don't know exactly how many clicks it will take, but you know when to stop.

This makes Click Until perfect for iterative interfaces: image carousels, pagination controls, increment/decrement buttons, and any UI where you need to click repeatedly to reach a goal.

## When to Use Click Until

Click Until is designed for scenarios where you need to click repeatedly based on a condition rather than a fixed number of times.

**Use Click Until when:**
- Navigating through carousels until specific content appears
- Clicking pagination until you reach a particular page
- Incrementing/decrementing counters to reach a target value
- Scrolling through slideshows to find specific slides
- Clicking "Load More" until all content is loaded
- Advancing through multi-step wizards until a condition is met
- Cycling through options until the right one is displayed
- You need to click an unknown number of times to reach a goal

**Don't use Click Until when:**
- You need to click a fixed number of times (use regular Click in a loop)
- The element should only be clicked once (use standard Click)
- The condition might never be met (could cause infinite loop)
- You need to interact with different elements (use separate Click actions)
- Timeout risk is high (consider manual iteration with safer controls)

## How It Works

Click Until operates with built-in condition checking:

1. **Initial State**: Captures current UI state
2. **Condition Check**: Evaluates if target condition is met
3. **Click or Stop**:
   - **Condition not met**: Clicks the element
   - **Condition met**: Stops clicking
4. **Repeat**: Returns to step 2
5. **Timeout Protection**: Stops after reasonable attempts to prevent infinite loops
6. **Final Verification**: Confirms condition was achieved

This cycle continues until either the condition is met or a safety timeout is reached.

## Platform Support

- **Web**: Full support
- **Mobile**: Not supported (web only)

Click Until is currently available only for web applications.

## Example Scenarios

### Scenario 1: Image Carousel

You're testing an image gallery where users click "Next" to browse through images. You want to find a specific image.

```
Test: "Find specific image in carousel"

1. Navigate to gallery page
2. Wait until: Carousel loads
3. Add prompt: "click on the next image until the car is visible"
4. Wait until: Car image is displayed
5. Click "View Details" on car image
6. Verify: Car details page loads
```

**Why Click Until works here**: You don't know which position the car image is in. Click Until keeps clicking "Next" until the car appears, regardless of how many clicks that takes.

**Why Click Until works here**: Rather than clicking "+" exactly 5 times, Click Until keeps clicking until the counter displays 5, handling any initial state.

## Best Practices

### 1. Define Clear Exit Conditions

Your "until" condition should be specific and achievable.

**Good:**
```
click next until the car image is visible
click plus until counter shows 5
click next page until "John Smith" appears in the list
```

**Problematic:**
```
click next until done  ← Too vague
click plus until enough  ← Unclear condition
click next until it looks right  ← Subjective
```

### 2. Ensure Condition is Achievable

Make sure the condition you're checking for can actually be reached.

**Good:**
```
click next image until the red car is visible
# You've confirmed the red car exists in the carousel
```

**Risky:**
```
click next image until the purple elephant is visible
# If no purple elephant exists, this will timeout
```

### 3. Add Verification After Completion

Confirm that clicking until the condition was met actually achieved your goal.

**Good:**
```
1. click the up button until you reach 5 on the counter
2. Wait until: Counter displays 5
3. Verify: Counter value is 5
```

### 4. Consider Timeout Implications

Click Until has timeout protection, but be aware of how long it might take.

**Good:**
```
click next until page 5 appears  ← Reasonable, will take ~5 clicks
```

**Risky:**
```
click next until page 1000 appears  ← Might timeout, takes forever
```

### 5. Use for Iterative Navigation Only

Click Until is for clicking the same element repeatedly, not different elements.

**Good:**
```
click next button until target slide appears
# Same "next" button clicked repeatedly
```

**Wrong approach:**
```
click different menu items until page changes
# Should use separate Click actions, not Click Until
```

## Common Pitfalls

### Pitfall 1: Unclear Stop Condition

**Problem:**
```
click next until ready
# What does "ready" mean? Condition is too vague
```

**Solution:**
```
click next until the "Submit" button appears
# Specific, observable condition
```

### Pitfall 2: Impossible Condition

**Problem:**
```
click next image until the dragon appears
# If no dragon exists in carousel, this will timeout
```

**Solution:**
```
Verify target content exists before using Click Until
Have fallback if condition can't be met
Monitor for timeout errors
```

### Pitfall 3: Using for Single Click Scenarios

**Problem:**
```
click the login button until the page changes
# Login button should only be clicked once
```

**Solution:**
```
click the login button  ← Standard Click
Wait until: Dashboard loads
# Use standard Click + Wait for single-click actions
```

### Pitfall 4: Not Handling Initial State

**Problem:**
```
click increment until counter is 5
# Counter might already be at 5, or at 10
```

**Solution:**
```
Option 1: Reset to known state first
1. click reset counter button
2. click increment until counter is 5

Option 2: Use absolute condition
1. click increment until counter is exactly 5 (handles any start)
```

### Pitfall 5: Forgetting Timeout Risk

**Problem:**
```
click load more until everything is loaded
# "Everything" might be thousands of items, causing timeout
```

**Solution:**
```
click load more until 100 items are visible
# Specific, achievable limit
# Or use alternative approach for massive datasets
```

## Comparison with Similar Interactions

### Click Until vs Click (Standard)

**Standard Click:**
- Behavior: Clicks once
- Best for: Single interactions
- Stops: After one click
- Use when: One click is sufficient

**Click Until:**
- Behavior: Clicks repeatedly
- Best for: Iterative navigation
- Stops: When condition is met
- Use when: Unknown number of clicks needed

**Decision rule**: Use standard Click for single actions. Use Click Until when you need to repeat until a goal is reached.

### Click Until vs Loop with Click

**Click Until:**
- Syntax: Single natural language prompt
- Condition: Checked automatically
- Stops: When condition true
- Simpler: One instruction

**Manual Loop:**
- Syntax: Multiple separate Click actions
- Condition: Manual checking
- Stops: After fixed iterations
- More control: Explicit loop logic

**Decision rule**: Use Click Until for condition-based iteration. Use manual loop if you need precise control or complex logic between clicks.

### Click Until vs Conditional Click

**Click Until:**
- Purpose: Repeat until goal reached
- Clicks: Multiple times
- Condition: Exit condition for loop
- Example: "Click next until item appears"

**Conditional Click:**
- Purpose: Click if element present
- Clicks: Once or not at all
- Condition: Whether to click at all
- Example: "If modal appears, close it"

**Completely different**: Click Until is for iteration. Conditional Click is for optional elements.

3. Add prompt: "click next image until image 10 is shown"

### Handling Edge Cases

Account for situations where condition might already be met:

```
Test: "Set counter (might already be set)"

1. Navigate to product page
2. Wait until: Page loads
3. Check current counter value
4. Add prompt: "click plus until counter is 5"
   # If already 5, won't click
   # If less than 5, will click until reaching 5
   # If more than 5, might timeout (needs handling)
5. Verify: Counter is 5
```

### Safety Limits

For scenarios with unknown limits, add explicit bounds:

```
Test: "Load content with safety limit"

Strategy 1: Limit by count
"click load more until 50 items are visible"

Strategy 2: Limit by content
"click load more until 'no more items' message appears"

Strategy 3: Combination
"click load more until 100 items are loaded or 'all loaded' appears"
```

## Troubleshooting Click Until

### When Click Until Times Out

If Click Until doesn't complete:

```
Checklist:
□ Does the target content actually exist?
□ Is the condition phrased clearly?
□ Is the element being clicked actually changing the state?
□ Is there a maximum number that makes sense?
□ Should you use a different approach?

Solutions:
- Verify target content exists before test
- Make condition more specific
- Add explicit timeout handling
- Consider alternative interaction pattern
```

### When Clicks Don't Change State

If clicks aren't having an effect:

```
Problem: Clicking but nothing changes

Diagnosis:
- Is element actually clickable?
- Are clicks registering?
- Is there a delay between clicks needed?
- Is JavaScript handling the clicks?

Solutions:
- Verify element is interactive
- Add small delays between clicks if needed
- Check if different click method needed (OCR, Smart Click)
- Consider if Click Until is right approach
```

## Key Takeaways

1. **Click Until is for iteration** - Repeatedly clicks until condition is met
2. **Define clear exit conditions** - Specify exactly what you're looking for
3. **Web only** - Currently not supported on mobile
4. **Condition-based stopping** - Stops when target state is reached
5. **Timeout protected** - Won't loop forever
6. **Use "until" language** - Indicates looping behavior in prompt
7. **For same element** - Clicks one element repeatedly, not different ones
8. **Ensure achievability** - Condition must be reachable
9. **Verify results** - Confirm condition was actually met
10. **Consider alternatives** - Sometimes manual loop with better control is better
