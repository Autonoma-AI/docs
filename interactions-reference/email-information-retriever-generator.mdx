## What is Email Information Retriever Generator?

The Email Information Retriever Generator creates temporary, unique email addresses that you can use in your tests. These aren't real email addresses that require you to set up accounts or manage inboxes—they're special test email addresses that Autonoma manages for you, complete with accessible inboxes you can read from during test execution.

Think of it as having an unlimited supply of disposable email addresses that:
- Are created instantly when needed
- Have working inboxes that receive emails
- Can be read by Email Information Retriever during tests
- Are automatically cleaned up after testing

This is the foundation of email testing in Autonoma. Without generating an email first, you can't retrieve information from emails. The generator creates the email address, your application sends emails to it, and the retriever extracts information from those emails.

## The Email Testing Challenge

Modern applications depend heavily on email for critical functionality:

**User Registration**
```
Problem: How do you test email verification without using real email accounts?
Solution: Generate test email, complete registration, retrieve verification code
```

**Password Resets**
```
Problem: How do you automate testing password reset flows that require email?
Solution: Generate test email, request reset, retrieve reset link from email
```

**Two-Factor Authentication**
```
Problem: How do you test 2FA that sends codes to email?
Solution: Generate test email, trigger 2FA, retrieve code from email
```

**Notification Testing**
```
Problem: How do you verify emails contain correct information without manual checking?
Solution: Generate test email, trigger notification, retrieve and verify content
```

**Traditional approaches fail:**
- **Real email accounts**: Require manual setup, checking, and maintenance
- **Mocking email**: Doesn't test actual email delivery and content
- **Skipping email steps**: Leaves critical functionality untested
- **Database manipulation**: Bypasses the real user flow

**Email Information Retriever Generator solves this** by creating test emails that work like real ones but are fully automated and disposable.

## How It Works

When you use Email Information Retriever Generator:

1. **Generation Request**: You specify what type of email testing you'll do (OTP, magic link, balance info, etc.)
2. **Email Creation**: Autonoma generates a unique, temporary email address
3. **Inbox Setup**: A working inbox is created for that email address
4. **Email Return**: The generated email address is provided for use in your test
5. **Email Receiving**: Any emails sent to this address are captured
6. **Information Retrieval**: Use Email Information Retriever to extract data from received emails

### Typical Flow

```
Generate:
1. Generate an email for otp
2. Extract generated email with key TEST_EMAIL

Use:
3. Fill registration form with {{key:TEST_EMAIL}}
4. Submit form

Retrieve:
5. Wait for email delivery
6. Retrieve the otp from the email
7. Extract code and use in application
```

## Best Practices

### 1. Generate Email at Start of Test

Generate email addresses before you need them:

**Good:**
```
1. Generate an email for otp
2. Extract email with key TEST_EMAIL
3. Navigate to registration page
4. Fill form with {{key:TEST_EMAIL}}
```

**Bad:**
```
1. Navigate to registration page
2. Fill form with... what email?
3. Generate an email for otp ← Too late!
```

### 2. Always Extract Generated Email

Always capture the generated email for use throughout your test:

**Good:**
```
1. Generate an email for otp
2. Extract generated email address with key USER_EMAIL
3. Use {{key:USER_EMAIL}} throughout test
```

**Bad:**
```
1. Generate an email for otp
2. Try to use the email... but it wasn't extracted
```

### 3. Use Descriptive Key Names

When extracting generated emails, use clear key names:

**Good:**
```
Generate an email for otp
Extract with key REGISTRATION_EMAIL

Generate an email for magic link
Extract with key PASSWORD_RESET_EMAIL

Generate an email for account balance
Extract with key NOTIFICATION_EMAIL
```

**Bad:**
```
Extract with key EMAIL
Extract with key EMAIL2
Extract with key TEMP_EMAIL
```

### 4. Match Email Type to Usage

Generate the appropriate email type for your use case:

**For OTP codes:**
```
generate an email for otp
```

**For password reset links:**
```
generate an email for magic link
```

**For account balance emails:**
```
generate an email for account balance
```

This helps the retriever understand what to look for later.

### 5. Generate Separate Emails for Multiple Users

When testing multi-user scenarios, generate distinct emails:

```
Setup:
1. Generate an email for otp
2. Extract with key USER_A_EMAIL

3. Generate an email for otp
4. Extract with key USER_B_EMAIL

5. Generate an email for otp
6. Extract with key USER_C_EMAIL

Use each email for its respective user throughout the test
```

### 6. Generate Fresh Email for Each Test

Don't reuse email addresses across different test cases:

**Good pattern:**
```
Test 1: "Registration flow"
1. Generate an email for otp
2. Use for registration test

Test 2: "Password reset flow"
1. Generate an email for magic link ← New email for new test
2. Use for password reset test
```

**Bad pattern:**
```
Test 1: "Registration flow"
1. Use {{variable:SHARED_EMAIL}}

Test 2: "Password reset flow"
1. Use {{variable:SHARED_EMAIL}} ← Reusing same email causes conflicts
```

### 7. Consider Email Context in Multi-Step Flows

If your test involves multiple emails to the same address, the context matters:

```
Test: "Complete onboarding with multiple verifications"

1. Generate an email for otp
2. Extract with key USER_EMAIL

3. Use {{key:USER_EMAIL}} for registration
4. Retrieve registration OTP from email

5. Use {{key:USER_EMAIL}} for phone verification
6. Retrieve phone verification code from email

7. Use {{key:USER_EMAIL}} for welcome email
8. Retrieve welcome information from email
```

The same email receives multiple emails, and the retriever understands the context based on your retrieval requests.

## Common Pitfalls

### Pitfall 1: Forgetting to Generate Email

**Problem:**
```
1. Navigate to registration page
2. Retrieve the otp from the email ← No email was ever generated!
```

**Solution:**
```
1. Generate an email for otp FIRST
2. Extract email address with key TEST_EMAIL
3. Navigate to registration page
4. Use {{key:TEST_EMAIL}} in form
5. Then retrieve the otp
```

### Pitfall 2: Not Extracting Generated Email

**Problem:**
```
1. Generate an email for otp
2. Input text: ??? in email field ← Email was generated but not extracted
```

**Solution:**
```
1. Generate an email for otp
2. Extract generated email address with key TEST_EMAIL
3. Input text: {{key:TEST_EMAIL}} in email field
```

### Pitfall 3: Reusing Emails Across Tests

**Problem:**
```
Test 1: Uses test@example.com
Test 2: Uses test@example.com
Tests interfere with each other
```

**Solution:**
```
Test 1:
1. Generate an email for otp
2. Extract with key TEST_EMAIL_1
3. Use {{key:TEST_EMAIL_1}}

Test 2:
1. Generate an email for otp
2. Extract with key TEST_EMAIL_2
3. Use {{key:TEST_EMAIL_2}}

Each test gets fresh email
```

### Pitfall 4: Wrong Email Type for Use Case

**Problem:**
```
generate an email for account balance
Then try to retrieve magic link from it
```

Mismatch between generation context and retrieval context.

**Solution:**
```
For magic links: generate an email for magic link
For OTP codes: generate an email for otp
For balance info: generate an email for account balance
```

Match the generation type to what you'll retrieve.

### Pitfall 5: Not Waiting for Email Delivery

**Problem:**
```
1. Generate an email for otp
2. Extract email with key TEST_EMAIL
3. Submit form with {{key:TEST_EMAIL}}
4. Retrieve the otp from the email ← Too fast! Email hasn't arrived
```

**Solution:**
```
1. Generate an email for otp
2. Extract email with key TEST_EMAIL
3. Submit form with {{key:TEST_EMAIL}}
4. Wait until: "Code sent" confirmation appears
5. Wait 5 seconds for email delivery
6. Retrieve the otp from the email
```

### Pitfall 6: Confusing Multiple Generated Emails

**Problem:**
```
1. Generate an email for otp
2. Generate an email for magic link
3. Generate an email for account balance
4. Retrieve the otp from... which email?
```

**Solution:**
```
1. Generate an email for otp
2. Extract with key OTP_EMAIL

3. Generate an email for magic link
4. Extract with key RESET_EMAIL

5. Generate an email for account balance
6. Extract with key NOTIFICATION_EMAIL

Clear naming prevents confusion
```

## Debugging Generation Issues

### Issue: Generation Failed

**Error:**
```
Failed to generate email address
```

**Possible causes:**
1. Service temporarily unavailable
2. Account limitations reached
3. Network connectivity issues

**Solutions:**
```
# Retry generation:
Wait 2 seconds
Generate an email for otp again

# Check account status:
Verify test account has email generation enabled

# Check network:
Ensure test environment can reach Autonoma services
```

### Issue: Email Not Received After Generation

**Problem:**
```
Generated email successfully
Application sent email to that address
But retrieval finds no email
```

**Possible causes:**
1. Application didn't actually send the email
2. Email delivery is delayed
3. Wrong email address used

**Solutions:**
```
# Verify email address was used:
Check form submission used the extracted email

# Add more wait time:
Wait 10 seconds instead of 5

# Check application logs:
Verify application actually sent email

# Verify email address:
Print or log the generated email to confirm it's being used
```

### Issue: Retrieved Wrong Information

**Problem:**
```
Retrieved information doesn't match what's needed
```

**Possible causes:**
1. Mismatch between generation type and retrieval type
2. Multiple emails received, retrieved from wrong one

**Solutions:**
```
# Match types:
If generating for magic link, retrieve magic link
If generating for otp, retrieve otp

# Be specific in retrieval:
"retrieve the registration otp from the email"
"retrieve the password reset link from the email"
```

- **Email Information Retriever**: Extract information from emails sent to generated addresses
- **Extract Information**: Capture data from your application's UI
- **Variables**: Store generated emails for reuse throughout tests
- **Random Data**: Generate other test data like names and passwords
