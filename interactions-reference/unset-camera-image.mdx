## What is Unset Camera Image?

Unset Camera Image is the cleanup companion to Set Camera Image. It removes any previously loaded camera image from Autonoma's memory, ensuring that subsequent camera interactions start with a clean slate.

Think of it as the "reset" button for camera testing. When you've used Set Camera Image to provide a test photo and that photo has served its purpose, Unset Camera Image clears it out so the next camera interaction doesn't accidentally reuse the same image.

What makes this interaction important is its role in test reliability and clarity. Without proper cleanup between camera captures, tests that involve multiple photos can become confusing—you might intend to capture a new photo but inadvertently use the previous test image. Unset Camera Image prevents this ambiguity by explicitly clearing the loaded image.

## When to Use Unset Camera Image

Unset Camera Image should be used whenever you need to ensure a clean camera state in your mobile app tests. Here's when it's the right tool:

**Perfect for:**
- Between multiple photo captures in the same test
- After completing a photo upload to prepare for the next one
- When testing "cancel camera" workflows (user backs out without capturing)
- Cleaning up test state before the next test step
- Preventing accidental image reuse in complex multi-photo flows
- Resetting camera state after photo rejection or retake
- End of test cleanup for better test isolation

**Required when:**
- Your test captures multiple different photos sequentially
- You want explicit control over when images are cleared
- Testing scenarios where users might cancel or retry photo capture
- You need to verify "no image set" states in your app
- Building test suites with multiple camera-dependent tests

**Optional when:**
- Your test only captures one photo (cleanup happens automatically at test end)
- Each test is completely isolated (no image persistence between tests)
- You immediately set a new camera image (overwrites the previous one)

**Not needed when:**
- Testing web applications (not applicable to web)
- Using Set File to Upload instead of camera features
- Your test has completed and no further camera interactions occur

## How It Works

When you use Unset Camera Image in Autonoma, here's what happens:

1. **Memory Check**: Autonoma verifies if a camera image is currently set
2. **Image Removal**: The stored image reference is cleared from memory
3. **State Reset**: Camera interaction state returns to "no image set"
4. **Cleanup Confirmation**: The operation completes, ready for next interaction
5. **Memory Release**: Associated image data is released (garbage collected)

From this point forward, any camera interactions will not have a pre-loaded image unless you explicitly set a new one with Set Camera Image.

## Platform Support

- **Web**: Not applicable (camera image setting is mobile-only)
- **Mobile**: Full support (Android and iOS)

Unset Camera Image is exclusively for mobile application testing where camera functionality is involved.

## Best Practices

### 1. Unset After Each Successful Capture

In multi-photo tests, unset after each successful photo to maintain clarity.

**Good:**
```
# Photo 1
1. Set camera image: photo1.jpg
2. Capture photo
3. Verify capture
4. Unset camera image ← Clean up

# Photo 2
5. Set camera image: photo2.jpg
6. Capture photo
7. Verify capture
8. Unset camera image ← Clean up again
```

**Less clear:**
```
# Photo 1
1. Set camera image: photo1.jpg
2. Capture photo

# Photo 2
3. Set camera image: photo2.jpg ← Overwrites, but less explicit
4. Capture photo
```

### 2. Unset Before Setting a New Image

For extra clarity, unset before setting a new camera image in complex flows.

**Extra clear:**
```
1. Set camera image: photo1.jpg
2. Capture photo
3. Verify success
4. Unset camera image ← Explicit clear
5. Set camera image: photo2.jpg ← Fresh start
6. Capture photo
```

**Also works:**
```
1. Set camera image: photo1.jpg
2. Capture photo
3. Set camera image: photo2.jpg ← Implicitly replaces
4. Capture photo
```

The first approach is more explicit and easier to understand.

### 3. Unset After Rejection or Cancelation

When users cancel or their photo is rejected, unset before the next attempt.

**Good:**
```
1. Set camera image: blurry-photo.jpg
2. Capture photo
3. Wait until: "Quality too low" error
4. Unset camera image ← Clear rejected photo
5. Set camera image: clear-photo.jpg ← New attempt
6. Capture photo
7. Verify: Success
```

### 4. Use Comments to Explain Unset Timing

Add comments in your tests to clarify why you're unsetting at specific moments.

**Good:**
```
1. Set camera image: profile.jpg
2. Click "Take Photo" button
3. Wait until: Photo captured
4. Unset camera image ← Clear after successful capture
5. Navigate to next screen
```

### 5. Unset at End of Camera Workflows

Even if optional, unset at the end of camera workflows for cleaner test state.

**Good hygiene:**
```
Test: "Upload profile picture"

1. Set camera image: photo.jpg
2. Click "Take Photo" button
3. Wait until: Upload completes
4. Verify: Profile picture visible
5. Unset camera image ← Clean up at end

# Next test starts with clean state
```

### 6. Don't Unset Before First Set

You don't need to unset before the first Set Camera Image of a test.

**Unnecessary:**
```
1. Unset camera image ← Not needed (nothing is set yet)
2. Set camera image: photo.jpg
3. Capture photo
```

**Better:**
```
1. Set camera image: photo.jpg
2. Capture photo
```

Tests start with a clean state automatically.

### 7. Consider Test Isolation

In test suites with multiple camera tests, each test should start fresh. Unset at the end helps, but Autonoma typically handles this automatically.

**Optional but good practice:**
```
Test 1: "Upload profile picture"
  - Set camera image
  - Capture and upload
  - Unset camera image ← Clean up

Test 2: "Upload product photo"
  - Set camera image ← Starts fresh anyway
  - Capture and upload
  - Unset camera image ← Clean up
```

## Common Pitfalls

### Pitfall 1: Unsetting Before Using Set Image

**Problem:**
```
1. Set camera image: photo.jpg
2. Unset camera image ← Removes it immediately
3. Click "Take Photo" button ← No image available
```

You unset the image before actually using it for capture.

**Solution:**
```
1. Set camera image: photo.jpg
2. Click "Take Photo" button ← Use it first
3. Wait until: Photo captured
4. Unset camera image ← Then clean up
```

### Pitfall 2: Forgetting to Unset in Long Tests

**Problem:**
```
Test: "Complete profile with photos"

1. Set camera image: photo1.jpg
2. Capture profile picture
# ... 50 more test steps ...
53. Set camera image: photo2.jpg ← Forgot to unset photo1
54. Capture cover photo
```

Long tests might have multiple camera captures far apart, and forgetting to unset can cause confusion.

**Solution:**
Unset immediately after each capture:
```
1. Set camera image: photo1.jpg
2. Capture profile picture
3. Unset camera image ← Clean up immediately
# ... other steps ...
50. Set camera image: photo2.jpg
51. Capture cover photo
52. Unset camera image ← Clean up immediately
```

### Pitfall 3: Unsetting After Image Already Cleared

**Problem:**
```
1. Set camera image: photo.jpg
2. Click "Take Photo" button
3. Test ends ← Image automatically cleared
4. Unset camera image ← Already cleared, unnecessary
```

Autonoma typically clears images at test end automatically, so final unset might be redundant.

**Solution:**
This isn't really a problem—unsetting when nothing is set is harmless. But you can skip the final unset if you prefer:
```
1. Set camera image: photo.jpg
2. Click "Take Photo" button
3. Wait until: Capture complete
# Test ends, image auto-cleared
```

### Pitfall 4: Assuming Unset Deletes the Image File

**Problem:**
Thinking unset deletes the actual image file from the server.

**Reality:**
Unset only clears Autonoma's memory reference to the image. The hosted image file itself is not deleted or modified.

**Understanding:**
```
Set camera image: https://example.com/photo.jpg
  ↳ Autonoma loads reference to this URL

Unset camera image
  ↳ Autonoma clears the reference
  ↳ The file at https://example.com/photo.jpg still exists unchanged
```

### Pitfall 5: Over-Unsetting in Simple Tests

**Problem:**
Adding unset calls everywhere even when not needed:
```
Test: "Upload single profile picture"

1. Unset camera image ← Unnecessary (nothing set yet)
2. Set camera image: photo.jpg
3. Click "Take Photo" button
4. Wait until: Upload complete
5. Unset camera image ← Unnecessary (test is ending)
```

**Solution:**
Only unset when it adds value:
```
Test: "Upload single profile picture"

1. Set camera image: photo.jpg
2. Click "Take Photo" button
3. Wait until: Upload complete
# Test ends naturally, no unset needed
```

## Comparison with Set Camera Image

### Set Camera Image

**Purpose:** Load a test image for camera capture
**When to use:** Before opening camera functionality
**Effect:** Next camera interaction uses this image
**Required:** Yes, to simulate camera capture

### Unset Camera Image

**Purpose:** Clear the loaded test image
**When to use:** After camera capture completes
**Effect:** Removes image from memory
**Required:** No (optional cleanup for clarity)

### Usage Pattern

```
Set Camera Image ← Load image
  ↓
Camera Interaction ← Use image
  ↓
Unset Camera Image ← Clear image (optional but recommended)
  ↓
Set Camera Image (next) ← Load new image for next capture
```

## Key Takeaways

1. **Cleanup companion** - Unset Camera Image is the cleanup counterpart to Set Camera Image
2. **Mobile-only** - Like Set Camera Image, it's exclusively for mobile testing
3. **Optional but recommended** - Not required, but improves test clarity
4. **Use after captures** - Unset after each successful photo capture in multi-photo tests
5. **Use after rejection** - Clear rejected photos before retrying capture
6. **Pattern: Set → Use → Unset** - Follow this pattern for clean, readable tests
7. **Not a file delete** - Unset clears memory reference, doesn't delete image files
8. **Automatic cleanup** - Tests auto-clear at end, but explicit unset is clearer
9. **Improves readability** - Makes multi-capture tests easier to understand
10. **Prevents confusion** - Eliminates ambiguity about which image is active
