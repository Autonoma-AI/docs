## What is Email Information Retriever?

The Email Information Retriever interaction extracts specific pieces of information from emails generated during your test execution. When your application sends emails containing verification codes, magic links, account numbers, or other dynamic data, this interaction captures that information so you can use it in subsequent test steps.

Think of it as reading your email inbox and pulling out exactly what you need—whether that's a 6-digit OTP code, a password reset link, an invoice number, or any other information your application sends via email.

This interaction is specifically designed to work with emails generated through Autonoma's email testing system, providing a seamless way to test complete workflows that involve email communication.

## The Email Testing Problem

Modern applications rely heavily on email for critical workflows:

**Registration and Verification**
```
User signs up → Receives verification email → Clicks link or enters code → Account activated
```

**Password Reset**
```
User requests reset → Receives reset email → Clicks magic link → Sets new password
```

**Two-Factor Authentication**
```
User logs in → Receives OTP code → Enters code → Access granted
```

**Transaction Notifications**
```
User completes purchase → Receives confirmation email → Views order number and details
```

**Without email testing**, these workflows are impossible to test end-to-end. You'd have to:
- Manually check real inboxes during test execution
- Skip email steps entirely (incomplete testing)
- Mock email sending (doesn't test actual email delivery)
- Use brittle workarounds (database queries, API calls to bypass email)

**With Email Information Retriever**, you can test these workflows completely:
```
1. Generate test email address
2. Complete registration with that email
3. Retrieve verification code from email
4. Enter code to complete registration
5. Verify account is activated
```

## When to Use Email Information Retriever

### Use Email Information Retriever when:

**Testing OTP/verification code flows**
```
Application sends 6-digit codes for 2FA
Need to extract code and enter it in the UI
```

**Testing magic link authentication**
```
Application sends passwordless login links
Need to extract and navigate to the link
```

**Testing password reset flows**
```
User requests password reset
Need to extract reset link from email
Click link and set new password
```

**Validating email content**
```
Application sends confirmation emails
Need to verify specific information appears correctly
Extract order numbers, account balances, transaction IDs
```

**Testing multi-step verification**
```
Registration requires email verification
Then phone verification
Then document upload with confirmation
Extract data from each step's notification email
```

**Testing notification accuracy**
```
User completes action
Receives notification email
Verify email contains correct, dynamic information
```

### Use alternatives when:

**Testing email sending itself**
```
If you only need to verify an email was sent
Use email delivery verification
Don't need to extract information from the email
```

**Testing static email content**
```
If email content doesn't contain dynamic data
Use standard email content verification
No need to extract specific values
```

**Testing without email generation**
```
If you haven't generated a test email
Use Email Information Retriever Generator first
```

## How It Works

When you use Email Information Retriever:

1. **Email Context**: You must have previously generated a test email using Email Information Retriever Generator
2. **Email Retrieval**: Autonoma accesses the inbox for that generated email address
3. **Content Analysis**: AI analyzes the email content to find what you're looking for
4. **Information Extraction**: The specific information (OTP, link, number, etc.) is extracted
5. **Value Return**: The extracted value is returned for use in subsequent steps

### Typical Flow

```
Setup:
1. Generate an email for OTP with Email Information Retriever Generator
2. Use that email address in registration form

Action:
3. Submit registration form
4. Wait for email to arrive

Retrieval:
5. Retrieve the OTP from the email
6. Extract the code

Verification:
7. Enter the OTP code in the application
8. Complete registration
```

## Best Practices

### 1. Generate Email First

Always use Email Information Retriever Generator before attempting to retrieve information:

**Wrong order:**
```
1. Submit registration form
2. Retrieve the otp from the email ← No email was generated!
```

**Correct order:**
```
1. Generate an email for otp
2. Extract generated email address with key TEST_EMAIL
3. Submit registration form with {{key:TEST_EMAIL}}
4. Wait for email delivery
5. Retrieve the otp from the email
```

### 2. Wait for Email Delivery

Add appropriate wait time between sending and retrieving:

**Too fast:**
```
1. Click "Send Code" button
2. Retrieve the otp from the email ← Email hasn't arrived yet!
```

**Good timing:**
```
1. Click "Send Code" button
2. Wait until: "Code sent" confirmation appears
3. Wait 5 seconds for email delivery
4. Retrieve the otp from the email
```

Email delivery typically takes 3-10 seconds. Add a wait to ensure the email has arrived.

### 3. Be Specific About What to Retrieve

Clear descriptions help the AI find the right information:

**Vague:**
```
get the code from the email
```

**Specific:**
```
retrieve the otp from the email
retrieve the 6-digit verification code from the email
```

**Very specific when multiple codes exist:**
```
retrieve the email verification otp from the email
retrieve the phone verification code from the email
```

### 4. Extract Retrieved Information

Always extract the retrieved information for later use:

**Missing extraction:**
```
1. Retrieve the otp from the email
2. Input text in verification field ← What text? No extraction!
```

**Proper extraction:**
```
1. Retrieve the otp from the email
2. Extract information about the verification code with key OTP_CODE
3. Input text: {{key:OTP_CODE}} in verification field
```

### 5. Handle Different Email Content Types

Be aware that emails can contain different types of information:

**For codes:**
```
retrieve the otp from the email
retrieve the verification code from the email
retrieve the 2FA code from the email
```

**For links:**
```
retrieve the magic link from the email
retrieve the verification link from the email
retrieve the reset link from the email
```

**For data:**
```
get the account balance from the email
get the order number from the email
get the invoice total from the email
```

### 6. Test Email Content Accuracy

Don't just retrieve—verify the content is correct:

```
1. Place order with total $99.99
2. Extract order total from UI with key UI_TOTAL
3. Wait for confirmation email
4. Get the account balance from the email
5. Extract order total from email with key EMAIL_TOTAL
6. Assert: Email total {{key:EMAIL_TOTAL}} matches UI total {{key:UI_TOTAL}}
```

### 7. Handle Multiple Emails

If your workflow sends multiple emails, retrieve from the correct one:

```
1. Generate an email for registration otp
2. Extract registration email with key REG_EMAIL
3. Generate an email for login otp
4. Extract login email with key LOGIN_EMAIL

5. Register with {{key:REG_EMAIL}}
6. Retrieve the otp from the email ← Gets registration OTP

7. Log in with {{key:LOGIN_EMAIL}}
8. Retrieve the otp from the email ← Gets login OTP
```

The retriever understands context and retrieves from the appropriate email.

## Common Pitfalls

### Pitfall 1: Not Generating Email First

**Problem:**
```
1. Navigate to registration page
2. Retrieve the otp from the email ← No email address was generated!
```

**Solution:**
```
1. Generate an email for otp
2. Extract generated email with key TEST_EMAIL
3. Navigate to registration page
4. Use {{key:TEST_EMAIL}} in form
5. Submit form
6. Retrieve the otp from the email
```

### Pitfall 2: Not Waiting for Email Delivery

**Problem:**
```
1. Click "Send Verification Code"
2. Retrieve the otp from the email ← Email hasn't arrived yet!
```

**Solution:**
```
1. Click "Send Verification Code"
2. Wait until: "Code sent" message appears
3. Wait 5 seconds for email delivery
4. Retrieve the otp from the email
```

### Pitfall 3: Ambiguous Retrieval Requests

**Problem:**
```
get the number from the email
```

Which number? Order number? Account number? Phone number? OTP code?

**Solution:**
```
retrieve the order number from the email
get the account number from the email
retrieve the otp verification code from the email
```

### Pitfall 4: Not Extracting Retrieved Data

**Problem:**
```
1. Retrieve the otp from the email
2. Input text: ??? in verification field
```

You retrieved it but didn't extract it for use.

**Solution:**
```
1. Retrieve the otp from the email
2. Extract information about the otp code with key OTP_CODE
3. Input text: {{key:OTP_CODE}} in verification field
```

### Pitfall 5: Assuming Email Format

**Problem:**
```
retrieve the 6-digit otp from the email
```

What if your application sends a 4-digit or 8-digit code?

**Solution:**
```
retrieve the otp from the email
retrieve the verification code from the email
```

Let the AI find whatever format the email actually uses.

### Pitfall 6: Not Verifying Email Content

**Problem:**
```
1. Complete purchase
2. Retrieve the order number from the email
3. Done
```

You retrieved the order number but didn't verify it's correct or that the email contains other expected information.

**Solution:**
```
1. Complete purchase
2. Extract order number from UI with key UI_ORDER_NUMBER
3. Wait for confirmation email
4. Get the account number from the email
5. Extract order number from email with key EMAIL_ORDER_NUMBER
6. Assert: {{key:EMAIL_ORDER_NUMBER}} matches {{key:UI_ORDER_NUMBER}}
7. Assert: Email contains order total
8. Assert: Email contains shipping information
```

## Debugging Retrieval Issues

### Issue: Email Not Found

**Error:**
```
Failed to retrieve information: No email found
```

**Possible causes:**
1. Email hasn't arrived yet (wait longer)
2. Email wasn't generated (use Email Information Retriever Generator first)
3. Application didn't send the email (check application logs)

**Solutions:**
```
# Add more wait time:
Wait 10 seconds for email delivery

# Verify email was generated:
1. Generate an email for otp FIRST
2. Then proceed with test

# Check email address was used:
Verify the generated email was actually used in the form
```

### Issue: Information Not Found in Email

**Error:**
```
Failed to retrieve information: Could not find OTP in email
```

**Possible causes:**
1. Email doesn't contain what you're looking for
2. Description doesn't match email content
3. Email format is different than expected

**Solutions:**
```
# Be more flexible:
Instead of: "retrieve the 6-digit otp from the email"
Use: "retrieve the otp from the email"

# Check email content:
Verify what the email actually contains
Update retrieval description to match

# Be more specific if multiple codes:
"retrieve the email verification code from the email"
"retrieve the phone verification code from the email"
```

### Issue: Wrong Information Retrieved

**Error:**
```
Retrieved code doesn't work when entered
```

**Possible causes:**
1. Retrieved wrong code from email
2. Email contains multiple codes
3. Code expired before entry

**Solutions:**
```
# Be more specific:
"retrieve the otp from the email"
"retrieve the password reset code from the email"

# Extract immediately after retrieval:
1. Retrieve the otp from the email
2. Extract information about otp with key CODE
3. Use {{key:CODE}} immediately

# Reduce delay:
Minimize time between retrieval and usage
```
