## What is Set File to Upload?

Set File to Upload is Autonoma's solution to one of the most challenging aspects of automated testing: file uploads. It's the interaction that bridges the gap between your file system and your application's file upload functionality.

Think of it as pre-loading the answer before the question is asked. Before your test clicks an upload button (which would normally open a file picker dialog), you use Set File to Upload to tell Autonoma: "When a file picker opens, automatically provide this specific file."

What makes this powerful is that it eliminates the impossible task of automating OS-level file dialogs. Traditional testing tools can't interact with your operating system's file picker—it exists outside the browser's security boundary. Set File to Upload sidesteps this entirely by preparing the file in advance, so when the dialog appears, Autonoma already knows which file to provide.

## When to Use Set File to Upload

Set File to Upload should be used whenever your test needs to upload files through standard file input controls. Here's when it's the right tool:

**Perfect for:**
- Profile picture uploads (JPG, PNG, WebP)
- Resume or CV submissions (PDF, DOCX)
- Document uploads (invoices, receipts, contracts)
- Data import features (CSV, XLSX, JSON)
- Image galleries and photo uploads
- Attachment features (support tickets, messages)
- Bulk file uploads (multiple documents)
- Any feature with a "Choose File" or "Browse" button

**Required when:**
- Your application uses standard `<input type="file">` elements
- Users click a button that opens their OS file picker
- You need to test the complete upload flow, not just the UI
- Your upload feature includes file validation or processing
- You're testing file-related error states (wrong type, too large)

**Not needed when:**
- Your application uses drag-and-drop only (though you can still use it)
- Testing mobile camera uploads (use Set Camera Image instead)
- The upload is purely visual/UI without actual file processing

## How It Works

When you use Set File to Upload in Autonoma, here's the complete process:

1. **File Selection**: You specify a file path from your local file system
2. **File Loading**: Autonoma reads the file and stores it in memory
3. **File Registration**: The file is registered with your test run
4. **Dialog Interception**: When your test clicks an upload button, Autonoma intercepts the file picker dialog
5. **Automatic Provision**: Autonoma automatically provides the pre-loaded file to the dialog
6. **Upload Execution**: Your application receives the file as if a user manually selected it
7. **Persistence**: The file remains available throughout the test run for repeated uploads

This process is completely transparent to your application. From your app's perspective, a user selected a file through the normal file picker.

## Platform Support

- **Web**: Full support (Chrome, Firefox, Safari, Edge)
- **Mobile**: Not supported (use Set Camera Image for mobile camera uploads)

Set File to Upload is specifically designed for web application testing where standard file input controls are used.

## File Path Specifications

Set File to Upload requires absolute file paths from your local file system. Understanding the correct path format for your operating system is crucial.

### macOS and Linux Path Format

On macOS and Linux, paths start with a forward slash:

```
/Users/username/Documents/test-files/image.jpg
/home/username/test-data/customers.csv
/Users/qa/Desktop/receipts/invoice-001.pdf
```

**Finding the absolute path on macOS:**
1. Right-click the file in Finder
2. Hold the Option key
3. Select "Copy as Pathname"
4. The absolute path is now in your clipboard

**Finding the absolute path on Linux:**
1. Open the file's location in your file manager
2. Right-click the file
3. Select "Properties" or "Copy path"

### Windows Path Format

On Windows, paths start with a drive letter:

```
C:\Users\username\Documents\test-files\image.jpg
C:\test-data\customers.csv
D:\test-files\resume.pdf
```

**Important**: In some contexts, you may need to escape backslashes:
```
C:\\Users\\username\\Documents\\image.jpg
```

**Finding the absolute path on Windows:**
1. Hold Shift and right-click the file
2. Select "Copy as path"
3. The absolute path is now in your clipboard

You can store file paths in test variables for reusability:


Then use them in your tests:
```

```

This makes it easy to update file paths globally if your test file directory moves.

## Best Practices

### 1. Set File Right Before Clicking Upload Button

Always set the file immediately before clicking the upload button. This makes the test sequence clear and logical.

**Good:**
```
1. Navigate to profile page
2. Wait until: Page loads
3. Set file to upload: /Users/test/images/profile.jpg
4. Click "Upload Picture" button
5. Wait until: Upload completes
```

**Less clear:**
```
1. Set file to upload: /Users/test/images/profile.jpg ← Too early
2. Navigate to profile page
3. Wait until: Page loads
4. Fill out other form fields
5. Click "Upload Picture" button
```

### 2. Use Descriptive Test File Names

Name your test files clearly so anyone reading the test understands what they are.

**Good file names:**
```
profile-pic-valid-jpg.jpg
resume-with-special-chars.pdf
customers-10-rows.csv
oversized-image-5mb.jpg
invoice-receipt-example.png
```

**Poor file names:**
```
test.jpg
file1.pdf
data.csv
img.png
```

### 3. Keep Test Files Small

Use small file sizes to keep test execution fast. Large files slow down uploads and don't provide additional test value.

**Recommended sizes:**
- Images: 500KB or less
- PDFs: 1-2MB or less
- CSV files: 100KB or less
- Excel files: 500KB or less

**Exception**: When specifically testing large file handling, use appropriately sized files (but keep them under 10MB).

### 4. Store Test Files in Version Control

Commit your test files to your repository so all team members and CI/CD environments have access to them.

```
your-project/
  ├── tests/
  └── test-files/
      ├── images/
      ├── documents/
      └── data/
```

Add to `.gitattributes` to prevent line ending issues:
```
*.jpg binary
*.png binary
*.pdf binary
*.xlsx binary
```

### 5. Verify Upload Success

Always verify that the upload completed successfully before continuing the test.

**Good:**
```
1. Set file to upload: /Users/test/images/profile.jpg
2. Click "Upload Picture" button
3. Wait until: Filename appears on page
4. Verify: "profile.jpg" is visible
5. Verify: Image preview shows uploaded picture
```

**Risky:**
```
1. Set file to upload: /Users/test/images/profile.jpg
2. Click "Upload Picture" button
3. Click "Save" button ← Might click before upload finishes
```

### 6. Test Different File Types

If your application accepts multiple file types, test each type to ensure proper handling.

```
Test Suite: "Document upload - all supported types"

Test 1: Upload PDF document
  - Set file to upload: test.pdf

Test 2: Upload DOCX document
  - Set file to upload: test.docx

Test 3: Upload TXT document
  - Set file to upload: test.txt
```

### 7. Use Absolute Paths, Never Relative

Always use absolute paths starting from the root of your file system.

**Good:**
```
set file to upload /Users/test/images/profile.jpg
```

**Won't work:**
```
set file to upload ./images/profile.jpg
set file to upload ../test-files/profile.jpg
```

### 8. Handle File Name Display Correctly

Many applications display the uploaded filename. Account for this in your verifications.

```
1. Set file to upload: /Users/test/receipts/dinner-receipt-2024-01-15.jpg
2. Click "Attach Receipt" button
3. Wait until: Filename appears
4. Verify: "dinner-receipt-2024-01-15.jpg" is visible
   # Note: Only the filename appears, not the full path
```

## Common Pitfalls

### Pitfall 1: Setting File After Clicking Upload Button

**Problem:**
```
1. Click "Upload Picture" button ← Opens file picker immediately
2. Set file to upload: /Users/test/images/profile.jpg ← Too late!
```

The file picker has already opened. Setting the file afterwards doesn't help.

**Solution:**
```
1. Set file to upload: /Users/test/images/profile.jpg ← Set first
2. Click "Upload Picture" button ← Then click
```

Always set the file *before* clicking the button.

### Pitfall 2: Using Relative Paths

**Problem:**
```
set file to upload ./test-files/image.jpg
set file to upload ../images/profile.jpg
```

Relative paths don't work because Autonoma needs to know the absolute location on your file system.

**Solution:**
```
set file to upload /Users/test/test-files/image.jpg
```

Always use absolute paths starting from your file system root.

### Pitfall 3: File Doesn't Exist at Specified Path

**Problem:**
```
set file to upload /Users/test/images/profile.jpg
```

If this file doesn't exist, the interaction will fail.

**Solution:**
- Verify the file exists at the specified path
- Double-check the path spelling and capitalization
- Make sure test files are committed to version control
- Use copy/paste to get exact paths (don't type them manually)

### Pitfall 4: Not Verifying Upload Completion

**Problem:**
```
1. Set file to upload: /Users/test/resume.pdf
2. Click "Upload Resume" button
3. Click "Submit Application" button ← Might submit before upload finishes
```

The submit button is clicked before verifying the upload completed.

**Solution:**
```
1. Set file to upload: /Users/test/resume.pdf
2. Click "Upload Resume" button
3. Wait until: "resume.pdf" appears on page
4. Verify: Upload complete indicator is visible
5. Click "Submit Application" button
```

Always wait for upload completion confirmation.

### Pitfall 5: Wrong File Type for Application Requirements

**Problem:**
```
1. Set file to upload: /Users/test/image.gif
2. Click "Upload Profile Picture" button
3. Error: "Only JPG and PNG files are allowed"
```

You're testing with the wrong file type.

**Solution:**
- Read your application's file type requirements
- Use test files that match the accepted formats
- Create separate tests for file type validation

### Pitfall 6: Reusing File Path Across Different Machines

**Problem:**
Your test uses `/Users/tom/test-files/image.jpg`, but your teammate is `/Users/sarah/` and CI is `/home/runner/`.

**Solution:**
- Store test files in your project repository
- Use consistent relative locations within the project
- Document where test files should be stored
- Consider using test variables for paths:
  ```
  Variable: TEST_FILES_DIR
  Value: /Users/tom/project/test-files

  Then: set file to upload {{variable:TEST_FILES_DIR}}/images/profile.jpg
  ```

### Pitfall 7: Testing with Unrealistic File Sizes

**Problem:**
Using a 50MB image to test profile picture upload when your application likely limits uploads to 5MB.

**Solution:**
- Use realistic file sizes that match production constraints
- Test the file size limit explicitly with separate tests
- Keep standard test files small for fast test execution

## Comparison with Similar Interactions

### Set File to Upload vs Set Camera Image

**Set File to Upload:**
- Platform: Web only
- Use case: Standard file input controls
- File source: Your computer's file system
- File types: Any (images, PDFs, CSVs, etc.)
- Interaction: Opens OS file picker dialog
- Best for: Desktop web applications

**Set Camera Image:**
- Platform: Mobile only
- Use case: Camera capture features
- File source: Simulated camera capture
- File types: Images only
- Interaction: Simulates taking a photo
- Best for: Mobile app camera features

**When to switch**: Use Set Camera Image when testing mobile apps that use camera capture functionality. Use Set File to Upload for standard file selection.

### Set File to Upload vs Drag-and-Drop

**Set File to Upload:**
- Method: Click button → File picker opens
- Setup: Set file, then click button
- Reliability: High (standard upload flow)
- Browser support: Universal

**Drag-and-Drop Upload:**
- Method: Drag file onto drop zone
- Setup: Currently not directly supported in Autonoma
- Workaround: Most drag-drop zones also have a "click to upload" fallback

**Best practice**: Even if your app supports drag-and-drop, test using the click-to-upload method with Set File to Upload. This tests the most common user flow and is more reliable to automate.

## Metadata and Return Values

When you use Set File to Upload, Autonoma stores metadata about the file. This metadata is returned and can be used in subsequent steps:

**Metadata includes:**
- File path (absolute path to the file)
- File name (just the filename, not full path)
- File size (in bytes)
- File type (MIME type)

**Example metadata:**
```json
{
  "path": "/Users/test/images/profile.jpg",
  "filename": "profile.jpg",
  "size": 245678,
  "type": "image/jpeg"
}
```

This metadata is primarily used internally by Autonoma to manage the file upload process, but it's helpful to understand what information is captured.

## Testing in CI/CD

When your tests run in CI/CD environments, file paths need to work on the CI server's file system.

**Best practices for CI/CD:**

1. **Store test files in your repository:**
```
your-project/
  ├── tests/
  └── test-files/
      └── images/
          └── profile.jpg
```

2. **Use project-relative paths in CI:**
If your CI environment checks out your repo to `/home/runner/work/project/`, and test files are in the repo, construct absolute paths based on the working directory:

```
Variable: TEST_FILES_PATH
Value (local): /Users/qa/project/test-files
Value (CI): /home/runner/work/project/test-files
```

3. **Verify files exist:**
Add a test step to verify test files are available:
```
1. Verify: Test file exists at {{variable:TEST_FILES_PATH}}/images/profile.jpg
2. Navigate to profile page
3. Set file to upload: {{variable:TEST_FILES_PATH}}/images/profile.jpg
```

4. **Keep files small:**
Small test files upload faster in CI environments, making your test suite more efficient.
