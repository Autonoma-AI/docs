## What is Double Tap?

Double Tap is an interaction that performs two rapid taps (or clicks) on an element, simulating the double-tap or double-click gesture that many interfaces use for special actions. Just like double-clicking a file to open it on your computer, or double-tapping an image to zoom in on mobile, Double Tap executes two quick successive taps on a target element.

The key characteristic of Double Tap is timing—the two taps happen in quick succession, making them register as a double-tap gesture rather than two separate single taps. This timing matters because many UIs treat double-taps differently from two individual taps.

Double Tap works across both web and mobile platforms, intelligently handling the different contexts of double-clicking (desktop) versus double-tapping (mobile).

## When to Use Double Tap

Double Tap is for interfaces specifically designed to respond to double-tap/double-click gestures.

**Use Double Tap when:**
- The interface explicitly requires double-tap/double-click
- Zooming into images or content via double-tap
- Selecting text or elements that need double-tap
- Activating "favorite" or "like" features with double-tap (e.g., Instagram)
- Opening items that require double-click (file managers, desktop apps)
- Triggering special modes or states via double-tap
- Playing/pausing media with double-tap
- The UI documentation specifies double-tap interaction

**Don't use Double Tap when:**
- Standard single tap/click works (use Click)
- The element doesn't respond to double-tap
- Two separate sequential clicks are needed (use two Click actions)
- Long press is the required gesture (use Long Press)
- Right-click is needed (use Right Click)

## How It Works

Double Tap executes two rapid taps with proper timing:

1. **Target Detection**: Identifies the element using visual object detection
2. **Position Calculation**: Determines exact tap location
3. **First Tap**: Executes first tap
4. **Brief Pause**: Waits minimal time (milliseconds)
5. **Second Tap**: Executes second tap at same position
6. **Gesture Recognition**: UI recognizes this as double-tap
7. **Action Triggers**: Interface responds to double-tap gesture

The timing between taps is calibrated to register as a double-tap gesture rather than two independent taps.

- **Mobile**: Full support (double-tap)

## Best Practices

### 1. Use Only When Genuinely Required

Verify that double-tap is actually needed, not just single tap.

**Good:**
```
Test interface manually first
Confirm single tap doesn't work
Confirm double-tap produces different result
Then use Double Tap in test
```

**Avoid:**
```
Using Double Tap "just in case" when single Click works fine
```

### 2. Wait for Previous Actions to Complete

Ensure UI is ready before double-tapping.

**Good:**
```
1. Navigate to page
2. Wait until: Images load
3. double tap on the image
```

**Risky:**
```
1. Navigate to page
2. double tap on the image  ← Image might not be loaded yet
```

### 3. Verify Expected Result

Confirm double-tap produced the intended effect.

**Good:**
```
1. double tap on post image
2. Wait until: Like animation appears
3. Verify: Like count increased
4. Verify: Heart icon is filled
```

### 4. Be Specific About Target

Clear target descriptions help accurate double-tap placement.

**Good:**
```
double tap on the first image in the gallery
double tap the red heart icon on the second post
double tap the profile picture in the header
```

**Less effective:**
```
double tap something
double tap the thing
```

### 5. Consider Platform Differences

Remember it's double-click on web, double-tap on mobile, but both use the same interaction.

**Good understanding:**
```
Web test: Double Tap translates to double-click
Mobile test: Double Tap translates to double-tap
Same instruction, platform-appropriate execution
```

## Common Pitfalls

### Pitfall 1: Using When Single Tap Works

**Problem:**
```
double tap the login button
# But single tap works fine for login
```

**Solution:**
```
Use standard Click for buttons that respond to single tap
Reserve Double Tap for gestures that genuinely require it
```

### Pitfall 2: Confusing with Two Separate Clicks

**Problem:**
```
Need: Click button A, then click button B
Wrong: double tap button A
```

**Solution:**
```
Double Tap: Two taps on SAME element rapidly
Two Clicks: Two separate Click actions on different elements or with time between
```

### Pitfall 3: Not Waiting for Element to Be Ready

**Problem:**
```
1. Trigger image load
2. double tap on image  ← Image might not be tappable yet
```

**Solution:**
```
1. Trigger image load
2. Wait until: Image fully renders
3. double tap on image
```

### Pitfall 4: Using on Non-Interactive Elements

**Problem:**
```
double tap on static text
# Text might not respond to double-tap
```

**Solution:**
```
Verify element is interactive and responds to double-tap
Use appropriate interaction for the element type
```

### Pitfall 5: Not Verifying the Result

**Problem:**
```
1. double tap on image
2. Proceed immediately without checking if zoom occurred
```

**Solution:**
```
1. double tap on image
2. Wait until: Zoom animation completes
3. Verify: Image is zoomed
4. Then proceed
```

## Comparison with Similar Interactions

### Double Tap vs Click

**Standard Click:**
- Gesture: Single tap/click
- Best for: Standard button presses
- Speed: One tap
- Use case: 95% of interactions

**Double Tap:**
- Gesture: Two rapid taps/clicks
- Best for: Special actions requiring double-tap
- Speed: Two rapid taps
- Use case: Interfaces designed for double-tap

**Decision rule**: Use Click by default. Only use Double Tap when interface specifically requires double-tap gesture.

### Double Tap vs Two Separate Clicks

**Double Tap:**
- Action: Two rapid taps on SAME element
- Timing: Immediate succession
- Purpose: Trigger double-tap gesture
- Example: Double-tap to zoom

**Two Click Actions:**
- Action: Two separate Click interactions
- Timing: Can have delay between
- Purpose: Two distinct actions
- Example: Click button A, then click button B

**Not interchangeable**: These are fundamentally different interaction patterns.

### Double Tap vs Long Press

**Double Tap:**
- Gesture: Two rapid taps
- Duration: Brief
- Best for: Quick actions (like, zoom, select)
- Platform: Web and Mobile

**Long Press:**
- Gesture: Press and hold
- Duration: Extended (1-2 seconds)
- Best for: Context menus, special options
- Platform: Web and Mobile

**Decision rule**: Check UI behavior. Does it need rapid double-tap or press-and-hold?
